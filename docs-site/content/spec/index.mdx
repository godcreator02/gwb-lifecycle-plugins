# 交接

**本页回答**：这个仓现在有什么活在路上、做到哪儿了、接手的人先看什么。

**此刻这一区是空的**，只有这一页导读。也就是说没有跨会话的活悬着：现状区讲的就是盘上的样子。

## 规矩

**目录即状态：有页就是有活在路上，做完删页。** 一件活一页，页头是验收清单，正文是实施方案，
随做随提交，中途每一次提交都是一份可交接的快照。做完把结论拆解归梁，设计进[现状区](/docs)、
决定落一张[轨迹卡](/trajectory)、没做的回[未来区](/future/overview)，然后把这一页删掉。
git 历史是它的档案，留着页只会多一份跟现状区互相矛盾的说法。

什么活值得升格成一页：**跨会话、跨模块、有未定选型**，三条占一条就写。装得进一个会话的
直接开工，写页的成本比活本身还大。

## 一页的骨架

```text
---
title: <一句话说清这件活>
description: <验收标准，一行>
---

## 验收
- [ ] 条目一（能被机器或人当场验的）
- [ ] 条目二

## 方案
散文。改哪几处、按什么顺序、门禁怎么跑。

## 进度
一行一次提交或一次会话，新的在上。
```

验收条目要写成**当场验得了**的样子。「命令跑通了」不算，「在隔离 home 里调一次回 ok，
条目状态是活的」才算：前者是感觉，后者有人能复核。
