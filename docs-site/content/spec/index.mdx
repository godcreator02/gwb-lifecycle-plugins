# 交接

**本页回答**：这个仓现在有哪些跨会话进行中的工作、做到哪儿了、接手的人先看什么。

## 现在进行中的

| 页 | 是什么 |
| --- | --- |
| [全生态机制定案](/spec/ecosystem-simplify) | 内核与全套插件的配合机制（依赖、home 与安装、开发循环、importmap、契约、卸载清理、检查）定成什么样、分五期怎么做；写插件的规矩已经写进现状区，页头的验收清单里还有没勾的 |

## 规矩

**目录就是状态：有页就是有工作没做完，做完删页。** 一件工作一页，页头是验收清单，正文是实施方案，
边做边提交，中途每一次提交都是一份可以交接的快照。做完把结论拆开放回各自的位置：设计进[现状区](/docs)、
决定写一张[轨迹卡](/trajectory)、没做的回[未来区](/future/overview)，然后把这一页删掉。
git 历史是它的档案，留着页只会多一份跟现状区互相矛盾的说法。

什么工作值得单独写一页：**跨会话、跨模块、有没定下的选型**，三条占一条就写。一个会话做得完的
直接开工，写页的成本比工作本身还大。

## 一页的结构

```text
---
title: <一句话说清这件工作>
description: <验收标准，一行>
---

## 验收
- [ ] 条目一（能被机器或人当场验证的）
- [ ] 条目二

## 方案
散文。改哪几处、按什么顺序、检查怎么跑。

## 进度
一行一次提交或一次会话，新的在上。
```

验收条目要写成**当场验证得了**的样子。「命令跑通了」不算，「在隔离 home 里调一次回 ok，
条目状态是 ACTIVE」才算：前者是感觉，后者有人能复核。
