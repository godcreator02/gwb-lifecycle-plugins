# 投来的反馈

**本页回答**：别的仓在用 devkit 的过程中投来了什么意见。一条一节，处理完删——周转区不是档案，
定下来的判据落轨迹卡。本仓自己反复做的操作候选在 [hatch](/feedback/hatch)。

## 2026-09-12 devkit 缺一条「往隔离 home 首装件」的路

来源：总控台（试 block-note 测试版 + devkit 调试闭环时撞的）。

`devkit.dev` 预设条目已在 `cordis.yml` 里（做的是 add 之后停用→启用重挂）。给刚 `devkit.home.new` 开出来的
空隔离 home **首次**装件只有两条路，都不对劲：`plugins.install` 经 MCP 调装的是 default（总线在哪个 home
就装哪个），对隔离 home 够不着；手动 pnpm add + 手写条目 + 重开全是能错的地方。

**建议**：补一条 `devkit.home.add`（`{ home, pkg, spec?, entryId? }`），或让 `devkit.dev` 对无条目的包自动走
首装。守卫照旧：只认 home 名不认端口、default 当场拒。

**顺带三条（同一轮实测撞见）**：

1. `devkit.home.new` / `home.open` 起的内核不带 `--disable-backgrounding-occluded-windows`，要看帧的件
   （截图、等帧、`--size` 查询）对这种 home 取证拿陈旧帧或挂住。统一带上，或给个透传口。
2. `devkit.dev` 隐含前置：目标 home 必须装着 `gwb-plugins`（开头要经它问条目表），空 home 直接跑会退；
   报错文案说清，或 `home.new` 提供带底座件的选项。
3. agent 侧绕法值得进说明书：**devkit 命令里凡传 Windows 路径一律用正斜杠**（`D:/unitfolders/...`）——
   ZCode 的 MCP 参数会把 `\\` 吃掉一层，进 JSON 就是 `\u` 坏转义，报错只说 Bad Unicode escape 不指根因。

**进展**（09-18）：顺带第 1 条 0.14.1 修了（`home.new` / `open` 带调试口就带遮挡开关）；第 2 条由
`home.new` 自动铺底座解决。剩主诉「首装自动化」与第 3 条（见下面 09-14 那条正斜杠）。

## 2026-09-14 前缀与变体的顺序写反了静默编不出规则——手册只暗示没明说，守卫也测不到

来源：总控台（第三轮 fresh-eyes 自举验收，功能题 gwb-timer，隔离 home 实跑）。

窗格样式写 `disabled:timer:opacity-50`：编译**一条规则都不出、也不报错**；写成
`timer:disabled:opacity-50` 才有。写插件手册里 `logger:group-hover:*` 的示例只暗示
「前缀在最前」，没有明说这条；模板的产物守卫只检查已编出的规则，对「源码里有这个类名、
产物里却没有」完全测不到。验收代理在这里走了本轮最大的一段弯路——写探针脚本用
`@tailwindcss/node` 逐条编译才定案（第一版探针还因摘了 prefix 得出「全都不出」的假结论）。
实测：`timer:disabled:*` 出规则，`disabled:timer:*` 与 `hover:timer:*` 都不出。

**投来的建议**：手册明写一句「前缀永远排最前；顺序写反不报错，只是没有规则」；更进一步，
模板产物守卫加一层「源码里出现的全类名 ⊆ 产物规则」的覆盖检查，把这类静默失败拦进门禁。

**进展**（09-18）：说明书那半写进了附件 `references/ui.md`；剩覆盖检查那半。

## 2026-09-14 「路径一律正斜杠」对 `devkit.scaffold` 不成立

来源：同上。

经 HTTP 门 curl 传含 Windows 路径的 JSON：`unit-folder.readFile` 吃正斜杠，
`devkit.scaffold` 的 `dir` **必须真反斜杠**——本仓 09-12 那张卡「凡传 Windows 路径一律用
正斜杠」的绕法在 scaffold 这里行不通，代理在 `bad json` 上来回试了好几轮（稳法见同日投给
base-plugins 的卡：body 落文件再 `--data-binary @file`，那条归 command-http 说明书）。

**投来的建议**：scaffold 与一切收路径参数的 devkit 命令统一吃正斜杠（入口处归一），让
「一律正斜杠」这条绕法全线成立。

## 2026-09-14 三条小的：client 半 import type 行给得太晚、测试 harness 的无参类型、首装条目复验

来源：同上。

1. client 半 tsconfig `"types": []` 不吃全局声明，`window.gwb` 要在文件头
   `import type {} from '@godcreator/gwb-plugin-api'` 才认。说明书里有这条信息
   （plugin-api ≥0.1.1 声明 `window.gwb`，实测属实），但埋得深——代理是先撞了编译错才回头
   找到的。建议把这一行提前到写码/窗格章节开头明写。
2. 模板测试里无参调 handler 类型不过（参数 `unknown` 不自动可省），代理把 harness 的
   handler 类型改成 `(args?: unknown)` 才过。建议模板直接给这个形状。
3. 本仓 09-12「往隔离 home 首装件」卡的复验结论：`devkit.home.new` **自动铺底座已管用**
   （基座七件，`devkit.dev` 不再因空 home 退）；首装仍要按 `devkit.dev` 回执里的指引手写
   `plugin-manager.add-entry`——指引清楚，但离那张卡要的自动化还差最后一步，建议那条不撤。

**进展**（09-18）：第 1 条写进了附件 `references/ui.md`「浏览器半」开头；剩第 2、3 条。

## 2026-09-18 audit-deps 全生态回执过大，经 MCP 工具调用会被客户端截断

来源：总控台（全生态依赖清账会话：12 个仓、30 余包发版，逐仓清账时反复要读这份账）。

现场：全生态 23 仓 / 45 清单 / 166 findings 时，`run devkit.audit-deps` 的回执 JSON 约 50KB——
经 MCP 门（`run`）调用超出客户端单次回执预算，**尾部被截断**：本会话第一次调用就丢了后半段
（gwb-reimburse / gwb-pomodoro 两段与 `byKind` 汇总）。绕法是把 `bin/client.mjs` 拿到命令行直跑、
重定向落文件再读（`run mcp.client` 那份说明书里有这支 CLI），全量拿得到——但得先知道要绕。

**投来的建议**：给 audit-deps 加一个可选过滤参数（如 `{ repo?: "<单元>/<仓>" }`，或 `{ only: [...] }`），
或让回执分两档（摘要 + 按仓索取）。清账的 agent 一轮能读完自己那一仓的账，不必落文件再解析。

## 2026-09-19 要追 shell 0.10：peer 会出范围，改个号就行

来源：gwb-ui-plugins（窗格模型第二版第一期；shell 0.10.0 今天发团队源）。

shell 0.10.0 按 gwb-release 抬了次版本号：开窗格的行为变了（本桌优先、从不切桌面，新窗格落在来源旁边，预览每组一个），
插件调用面只增不减。`plugins/devkit` 对外壳是可选 peer（`^0.9.2`），装上 0.10.0 会出 peer 警告。本仓不调开窗格，
追法就是 dev 钉与 peer 下限抬到 `0.10.0`、跑 check，下次发版时带上。

## 2026-09-22 页面加载后才补装的 peer 不进 importmap——devkit.dev 首装流的重载时机偏早

来源：gwb-block-note（v2 引擎线第 2 单验收，隔离 home bn-v2-2609222003）。

现场：`devkit.dev` 首装（回执 note 指引走 `plugin-manager.install` 建条目）之后，install 发现缺 peer
（`@godcreator/block-note`）顺手补装——但**整页重载在 devkit.dev 那一步早就做完了**，importmap 是页面
加载那一刻按当时的 node_modules 拼的快照，后补的 peer 不在表里。首开窗格，浏览器端产物里
`import "@godcreator/block-note"` 解析不到，窗格里一整行红：「加载失败：TypeError: Failed to resolve
module specifier "@godcreator/block-note"」。整页重载一次即愈（快照重拼）。两个坑上加坑的点：node 侧
日志**全程无 error**——它只在渲染层现形，devkit.dev 的日志基线测不到；且窗格源码没错、装也没错，纯看
「挂上了 / 条目 ACTIVE」全绿。

**投来的建议**（修的落点在 plugin-manager 那半，devkit 这边至少要把话写进说明书）：`plugin-manager.install`
补装过 peer 后自己触发一次整页重载（与 update-all 同款），或 devkit.dev 的回执 note 在「首装建条目」那句后面
带上「install 若补装了 peer，建完条目再整页重载一次」。顺带给验收纪律补一句：带浏览器端的件，实装验证要配
截图或窗格渲染取证——这类坑只有渲染层会喊。

## 2026-09-25 块笔记已撤掉 `gwb.shared`，定案第四节与第六节在块笔记一侧做完

来源：块笔记仓（gwb-block-note）把引擎替换合回 main 之后按全生态机制定案对齐的会话。

定案第四节「块笔记的解析库撤掉 `gwb.shared`，块笔记系列插件各自打包进构建产物」与第六节「外置名单只从提供方读」，块笔记与论文插件的 main 上
都已改完：界面包 `@godcreator/block-notebook-ui` 不再声明 `gwb.shared`、去掉 `gwb` 关键词，不再装进 home；各插件浏览器端只外置内核包清单
`gwb.shared` 的键。同一轮还照写插件的规矩改了几处：命令表抽成无状态的包 `@godcreator/block-notebook-commands`（插件之间不再 import
核心插件的 `./shared`）；`blockNoteLibraries` / `blockNoteExtensions` 继承 `Service`；核心插件卸载时关库的清理返回 promise（第八节）；
契约版本号对不上拒绝加载（第七节）；核心插件补回 `gwb.provides`。都还没发版。
定案「已决定（2026-09-24）」里等块笔记撤声明的那一条，条件已满足，可以更新；删机制本身在内核仓（已另投一条），要等 default 切换卸掉旧的
`@godcreator/block-note` 之后。
