## 2026-09-12 devkit 缺一条「往隔离 home 首装件」的路

来源：总控台（试 block-note 测试版 + devkit 调试闭环时撞的）。

`devkit.dev` 预设条目已在 `cordis.yml` 里（做的是 add 之后停用→启用重挂）。给刚 `devkit.home.new` 开出来的
空隔离 home **首次**装件只有两条路，都不对劲：`plugins.install` 经 MCP 调装的是 default（总线在哪个 home
就装哪个），对隔离 home 够不着；手动 pnpm add + 手写条目 + 重开全是能错的地方。

**建议**：补一条 `devkit.home.add`（`{ home, pkg, spec?, entryId? }`），或让 `devkit.dev` 对无条目的包自动走
首装。守卫照旧：只认 home 名不认端口、default 当场拒。

**顺带三条（同一轮实测撞见）**：

1. `devkit.home.new` / `home.open` 起的内核不带 `--disable-backgrounding-occluded-windows`，要看帧的件
   （截图、等帧、`--size` 查询）对这种 home 取证拿陈旧帧或挂住。统一带上，或给个透传口。
2. `devkit.dev` 隐含前置：目标 home 必须装着 `gwb-plugins`（开头要经它问条目表），空 home 直接跑会退；
   报错文案说清，或 `home.new` 提供带底座件的选项。
3. agent 侧绕法值得进说明书：**devkit 命令里凡传 Windows 路径一律用正斜杠**（`D:/unitfolders/...`）——
   ZCode 的 MCP 参数会把 `\\` 吃掉一层，进 JSON 就是 `\u` 坏转义，报错只说 Bad Unicode escape 不指根因。
