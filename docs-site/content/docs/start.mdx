# 怎么用

**本页回答**：这个插件怎么装、装完要配什么、此刻它开出来的入口各在什么时候用、改完代码跑哪几条。

## 装

```
plugin-manager.install {"pkg":"@godcreator02/gwb-devkit"}
```

装完下一次 `/surface` 现扫就有——门没有会话，没有重连这个动作。

挂上了的证据在 `<home>\gwb.log` 里那句「开发套件就绪」。读那一行，不要读「装完了」这四个字：包装进 `node_modules` 与插件真的挂上是两件事。此刻这个 home 上到底有哪几条命令，以 `/surface` 的回执为准。

## 两个设置项

{/* ref file="../src/index.ts" lines="180-194" */}

`registry-dir` 是本机 Verdaccio 那个目录，含 `config.yaml`、`storage` 与 `node_modules/verdaccio`。不填，`registry.*` 三条全部回一句「未配置 registry-dir」。

`kernel-dir` 是内核仓的根，即含 `apps/desktop` 的那一级。不填，`devkit.home.new` 与 `devkit.home.open` 不工作；列与删不受影响。

两项都不给默认值。目录是这台机器的事实，编一个出来只会得到「配置了但不在」的假象，而那种假象要等到第一次真跑才炸。

## 六组入口

参数形状以命令自己的 description 为准。命令总线不带参数 schema，description 那一句就是调用方能看见的全部，所以它写得出形状；这一页只说什么时候用哪一组。

**建仓**。`devkit.scaffold` 把一个新插件的骨架落进一个新文件夹，默认连文档站一起建。目标目录必须还不存在。站那半是两步，经命令总线转给站点插件与 docfirst 插件，哪个插件没装就跳过那一步，插件那半照样落盘。参数给错会把整份说明回给你，不必背。

**本机源**。`registry.status` 查、`registry.up` 拉起（已经在跑就直接接管）、`registry.down` 停，三条都无参数。这台机器上别的仓也在用这个源，停之前想清楚。起不来的时候错话里带着日志文件的绝对路径，读它就是了，没有一条专门回日志的命令。

工作台没起的时候走同一份逻辑的另一个入口：`node <包根>/bin/registry.mjs <status|up|down> <registry 目录>`，回执是一段 JSON，成了退出码 0、没成 1。首启要从源上装插件，那时工作台还起不来，所以这条路非有不可。

**测试 home**。`devkit.home.new` 开一个新的，名字长成 `<短名>-<时间戳>`，先 build 内核；`devkit.home.list` 列全部与谁在跑，连带两个端口（调试端口与命令口端口）；`devkit.home.open` 重开一个已有的且不 build；`devkit.home.rm` 删。一次验证开一个新 home，清理放在开新的那一刻，回执里本来就带着现有清单。

机器重启之后回到原来那个现场只有 `open` 这一条路：`new` 永远造新目录，插件得全部重装一遍。

**调试端口不收，起的时候自己挑**。先沿用这个 home 上次那个端口，被别人占了才另挑，换了会在回执的 `cdpNote` 里说一句。端口稳定下来是有价值的：人记得住、日志里对得上、开着的检查器不用换地址；而收一个手给的端口，剩下的全部用法就只有「敲错一位落在别人的端口上」。

`rm` **没在跑的直接删；还在跑的要 `force`**，那时连停带删，停的是哪个 pid 写在回执里。停它认的是内核开机写下的 `runtime.json`，所以手工敲 electron 起的那些同样停得了。`default` 是日常那份：不 `force` 不删，而且**它正跑着的时候 `force` 也不删**——自己关掉那扇窗再来。

**改一版看一版**。`devkit.dev` 一条走完从构建到取证。下一节单独说。

**在页面里动手**。`devkit.cdp` 是经 `gwbNodeCli` 登记的外部 CLI，连上一个工作台页面发真鼠标、真按键、截图，也能在那张页上跑工作台命令、刷新、问它是哪个 home、把一个文件送进页面里跑（`eval <文件> [JSON 参数]`，文件里写 `(args) => 一张表`）。

{/* ref file="../src/index.ts" lines="429-436" */}

十二个动作与五个开关的表在 `bin/cdp.mjs` 的文件头，那份随包发，是唯一的真相。**第一个位置只收 home 名**，给数字当场拒；端口从那个 home 的记录里查，连上之后还要拿页面自报的名字核对一次。**只对隔离 home 用，绝不打 `default`**：这儿发的是真操作，会真往库里写。内核起的时候要带 `--remote-debugging-port=<端口>` 与 `--disable-backgrounding-occluded-windows`，后一个不带，窗口被别的窗口盖住时 Chromium 停止产帧，截图拿到的是陈旧帧。

**手册**。写插件的整条路、八条红线、验机怎么走，在随包发的说明书 `gwb-devkit` 里，经 `skill.read` 取。

## 改一版看一版

{/* ref file="../src/index.ts" lines="467-474" */}

`devkit.dev` 走的是一条链：仓根构建，给每个包发一个开发版到本机源（号打成 `<patch+1>-dev.<戳>`，标 `dev` 不动 `latest`），在目标 home 里装那个准确的号，把对应条目停用再启用，整页重载，最后取证。取不到证就回 `ok: false`。

**构建与源都不可给。** 跳过构建就是发上一版，而回执一切正常；源这台机器上只有一个。少一个参数就少一条「给你一次机会跳过一道守卫」的岔路。

**目标只有一种指法：说出 home 名。** 这条命令不收端口，给了 `cdp` 当场拒，回一句教新写法的话：

{/* ref file="../src/index.ts" lines="447-459" */}

端口是查出来的，查的时候顺带验活：记录读得出、pid 还活着、那个 pid 真的持着那个端口，三道都过才动手。

**为什么端口不是地址。** 它是一个没有语义的数，敲错一位就落在另一个现场，而那个现场会老老实实收下你这一趟的发版、装包与重挂，事后也看不出哪儿不对。名字有拼写、有记录、有交叉核对，三样端口都没有。代价写在这儿：**记录坏了、或者起它的内核太旧的 home 就够不着**，那时停掉重开一次就有了；这支驱动也从此连不了非 gwb 的 Chromium 窗口。

**名字还带来一道核对。** 名字接着传进链里，每一步连上页面都跟页面自报的名字对一次：记录回答「你要的是哪个」，页面回答「你连上的实际是哪个」。端口会被下一个进程占走，记录会陈旧，只信记录就会静默推给另一个 home。链里那七步都是按名字调驱动的，为的就是每一步都白得这一道，而不是七次没人看着的重新定位。

**它住控制台那个 home，操作另一个 home**。换插件那一步要把条目停用再启用，工具自己要是跑在被换的那个 home 里，换到总线、外壳、命令口或它自己头上时，调用方跟着下线。所以盘那半（构建、发版、装）在本进程做，页那半（重挂、刷新、取证）经 CDP 送到目标页去。

两道守卫会当场拒：目标是 `default`，或者目标就是本插件自己所在的那个 home。前者是开发版进了日常那份 home，号看着跟正式版没两样而界面上一点异常都看不出来；后者是这条命令把自己停掉。换 devkit 自己走另一条路：发正式版，再 `plugin-manager.update-all`。

取证这一步不能省。重挂了、刷新了都不等于验过了：插件的 `apply` 里一条 async 静默 reject，现象正好是「挂上了但什么都没发生」。所以最后回头看两样，条目是不是真的 ACTIVE，以及这一趟的日志增量里有没有 error。

**取证只发生在链里头那一次**，因为判定要基线：哪些 error 是这一趟自己惹出来的，只有拿装包之前那个日志长度才分得出来。要现看一眼某个 home 的条目表，`devkit.cdp {"args":["<名>","cmd","plugin-manager.list"]}` 就是，那是看，不是验。

## 门禁

{/* ref file="../package.json" lines="24-30" */}

```
pnpm check          # typecheck + vitest
pnpm build          # 一趟 tsc 直出 dist/，没有打包器
```

**`pnpm check` 不构建。** 它吃的是源码，全绿只说明源码站得住，跟「装出来能不能跑」是两件事。发版前那次构建靠 `prepublishOnly` 这条脚本兜着，删了它，publish 会把上一版的 `dist/` 原样发出去而且一声不吭，现象是插件挂上了但新写的东西全没生效。

文档站的检查不在 `pnpm check` 里，它要起文档站的解析链，太慢。单独在 `docs-site` 里跑：`pnpm doc` 核对，`pnpm doc:confirm` 重钉（先 commit，git 比较器只认已提交的内容），`pnpm doc:render` 重摆生成物。

## 发一版

先抬 `package.json` 的版本号，同一个号永不重发，发之前先问一句它在不在源上。然后 `pnpm publish --registry http://127.0.0.1:4873/ --no-git-checks`。

发完就去升 default，别攒着：人在插件窗格点「全部更新」，或者调 `plugins.update-all`。手册与命令都随包走，不升等于 agent 读到的还是上一版，而它照着一份过期手册干活不报错。

整条路的细节、发版前先在隔离 home 验那一步、以及验机的几条纪律，在说明书 `gwb-devkit` 里，这一页不复述。
