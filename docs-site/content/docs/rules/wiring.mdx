# 插件之间的依赖记在哪

**本页回答**：有文档站的插件仓要把插件之间的哪些依赖记下来、记成什么格式、记在哪；谁来保证它写对。

## 约定

**有文档站的插件仓，把本仓每个插件跟别的插件之间的依赖记下来；记在哪一页不固定，每个插件的首页写明记在哪、链过去。**

- **记在哪**：整个仓写一页（本仓是[插件之间怎么连](/docs/wiring)，文件 `docs/wiring.mdx`），或者写在各插件首页的依赖一节里，都行；页名与文件名不固定
- **首页写明记在哪**：插件首页讲依赖的那一节写一句话链到记依赖的地方；就记在首页本节的，直接写表。同一份依赖只写一处，不写第二份

每个插件记三张表：

```mdx
## <插件包名>

### 提供

| 类别 | 名字 | 说明 |

### 注入

| 服务 | 提供方包 | 必需 / 局部注入 | peer 写法 | 用来做什么 | 缺了会怎样 |

### 按名字调用与约定通道

| 通道 | 对方 | 名字 | 用来做什么 |
```

- **提供**：服务、命令、事件、说明书、窗格、给别的插件按值 import 的主入口导出
- **注入**：源码里注入的每个服务，连同不写进 `inject`、用 `requireKernel` 取的 `gwbKernel`；peer 怎么写照[用到的插件写 peer](/docs/rules/plugin-peers)：写在 `export const inject` / `static inject` 里的是普通 peer，只在 `ctx.inject([...], fn)` 里用的标 `optional: true`
- **按名字调用与约定通道**：按命令名调用的别的插件的命令、推送或接收的事件、共享的 id、直接读写的别人的文件（`runtime.json`、`cordis.yml`、别的 home 的清单）、loader 与 cordis 的内部状态、子进程与网络
- **钉码按内容钉**：表下面用 `has file=… text=…` 钉在服务名、`inject` 写法、peer 条目、命令名、文件名这些字面量上，不用行号钉。表里钉的都是散在各文件里的一行字面量，行号钉在无关的改动之后就对不上，逼着人一遍遍确认；字面量改了，按内容钉的才真的该报

## 谁来保证它写对

没有工具查：`devkit.release` 不看仓里有没有文档站、依赖记没记。记下来的字面量由那一页自己的钉码守着，源码里的字面量改了，文档站的 `docfirst check` 报出来；源码里新加了注入、表没跟上，靠改代码的人同一个提交里补上。

peer 写得对不对另有检查：`devkit.release` 扫源码里的注入，提供方要写在 peer 里，见[用到的插件写 peer](/docs/rules/plugin-peers#源码注入由谁查)。

为什么只是约定、不作为发版的前提，见轨迹卡[wiring 页只作约定，发版不查](/trajectory/2026-09-25-wiring-page-convention-only)；为什么不固定记在哪一页，见轨迹卡[依赖记在哪一页不固定](/trajectory/2026-09-30-wiring-location-not-fixed)。
