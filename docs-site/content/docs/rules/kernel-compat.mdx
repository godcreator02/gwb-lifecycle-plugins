# 兼容哪个内核

**本页回答**：插件怎么声明自己兼容哪些内核；范围怎么算「包含」；谁在什么时候查；内核升级之后插件要做什么。

## 规则

**插件包在 `peerDependencies` 里写内核包 `@godcreator/gwb-kernel-desktop`，范围写 `^x.y.z`，x.y.z 是验证这个插件时所用的内核版本。** 范围包不包含验证时那个内核，由写插件的人在隔离 home 里验过之后保证。只查插件包（`keywords` 里有 `gwb-plugin`），库和工具包不写。

内核包和 `cordis` 一样装在每个 home 的根上（安装包只带启动器，启动器从 home 里加载内核），所以兼容性用标准的 peer 写：pnpm 把它解析到 home 里装着的那一份，安装时顺带比一次范围（只警告）。插件运行时不 import 内核包，只从它的包根 `import type` 接口类型（`GwbContext` 等），编译后不留 import；这条 peer 声明兼容哪些内核，也让 pnpm 把内核包装进插件的 `node_modules`，类型检查、构建脚本与发版前检查都从那里读它。

## 范围怎么算包含

只认 `^x.y.z` 一种写法，精确号、`>=`、`~`、少一段、带预发布段的都不算写对。主版本号为 0 时次版本号相同、主版本号 ≥1 时主版本号相同，并且不低于 x.y.z。只比 x.y.z 三段、预发布段不看，所以同一条线上的开发版内核也算在范围内。`^0.3.0` 包含 `0.3.0`、`0.3.4`、`0.3.1-dev.202609241500`，不包含 `0.2.7`、`0.4.0`；`^1.4.0` 包含 `1.9.2`，不包含 `1.0.0` 与 `2.0.0`。

{/* ref file="../plugins/plugin-manager/src/kernel-compat.ts" lines="32-44" hash="12b7f5f720cb" blob="b88e71e1b482" */}

这和内核的版本号规矩对得上：内核改了接缝上已有的东西——包括升级 loader、include 的版本、改 home 的布局、删改包根导出的接口类型——就升 x，插件写的范围不再包含新内核，所有插件都要在新内核上重新验过。只加东西的内核版本升 y，范围照样包含，插件的声明照样有效。

## 谁在查

**`devkit.release` 发版前检查**：对每个要发的插件包，peer 里没写内核包、写法不是 `^x.y.z`，两种都拒，一个包都不发；拒绝理由里写着改成 `^<验证时那个内核的版本号>`。范围包不包含哪个内核它不查：发版前检查能拿来比的只有调 `devkit.release` 的那个 home 里的内核，比了的话能不能发版就取决于从哪个 home 调：

**`plugin-manager.list` 按包报**：拿插件 peer 里内核包的范围和 home 里装的内核比，不包含的按包报出来。它只报告，不阻止加载（回执怎么读见插件管理那组页面里的[同名一页](/docs/plugin-manager/kernel-compat)）。

比对规则只有一份，在插件管理的 `src/kernel-compat.ts`；devkit 的发版前检查从插件管理的主入口 import 其中判断写法的 `isCaretRange`，两处认的写法一定相同（见[peer 里的内核包与插件](/docs/seams/kernel-peer)）。

## 内核升级之后

1. `plugin-manager.list` 里报出来的，就是 peer 范围不包含新内核的插件
2. 在隔离 home 里用 `devkit.dev` 验一遍（隔离 home 里装的是新内核）
3. 验过了，把 peer 里内核包的范围改成 `^<新内核的版本号>`，按补丁升自己的版本号，再 `devkit.release`

没验就改这个范围，等于撒谎：范围的下限是「在这个内核上验过」的声明，不是愿望。

## 为什么

插件管理这类插件依赖 loader 条目树之类内核没写进文档的结构，内核一改就可能把它弄坏；与其让内核维护一份下游名单、改动时逐个通知，不如每个插件自己声明兼容的内核范围，由插件管理在 home 里报告对不上的插件，由发版前检查拦下没写或写错的声明。内核包装在 home 里之后，这份声明就能用 peer 这个标准写法表达，不用另造清单字段，pnpm 安装时也会顺带检查。home 里拿内核包的范围比装着的内核（「在这个内核上验过」），peer 里别的插件比的是源上的 latest 在不在同一条线（「上游有没有出破坏性版本」），见[用到的插件写 peer](/docs/rules/plugin-peers)。
