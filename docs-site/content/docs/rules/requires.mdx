# 要求别的插件的最低版本

**本页回答**：插件怎么声明运行时要求 home 里别的插件最低到哪个版本；什么时候该写、写哪几个包；谁在什么时候查；为什么是清单里的字段加报告。

## 规则

**插件用到别的插件在某个版本才加上的东西时，在 `package.json` 的 `gwb` 字段里写 `requires`：`{ "<包名>": "<最低版本号 x.y.z>" }`。** 含义是运行时 home 里装的那个包不低于这个版本。这个字段可选，只写自己真用到了新东西的包。写进去的每个包也要写在 `devDependencies` 里，要求的版本不高于 dev 范围的下限。

## 怎么判

- **该写**：用到的东西是那个插件某个版本才有的，而它太旧时不报错、只是静默失效。典型是外壳新加的主题令牌：外壳太旧时 `var(--令牌名)` 取不到值，页面照样显示，只是样式不对。版本号写新东西第一次出现的那一版
- **不用写**：用到的东西一直都有；或者提供方太旧时本来就会报错——inject 的服务不在，cordis 让插件停在等待状态，`plugin-manager.list` 里看得到它没在运行；调一条不存在的命令，回执直接说命令不存在
- **共享数据格式、命令结构不靠它**：几个插件读写同一份磁盘数据、或依赖同一组命令的结构时，照[插件之间怎么交互](/docs/rules/interaction)按区间比对契约版本，区间外拒绝加载。`gwb.requires` 只报告，拦不住加载
- **最低版本号只写 x.y.z**：不写 `^`、`>=`，不带预发布段
- **要求的版本不高于 dev 下限**：dev 写 `^0.5.0` 时，本地开发、验证用的是 0.5.x 里的某一版；要求写 `0.5.1`，就是要求了一个本地没验过的版本。要求更高的版本，先把 dev 升上去、跑 check、在隔离 home 里验过

## 谁在查

**`devkit.release` 发版前检查**：插件包（`keywords` 含 `gwb-plugin`）写了 `gwb.requires` 才查，下面四种都拒，一个包都不发：不是对象；某个值不是合法的 x.y.z；某个包没写在 `devDependencies` 里；要求的版本高于 dev 范围的下限。dev 写 `workspace:` 的包不比下限：同仓的包本地用的就是工作区里的当前版本。

## 例子

一个插件用了外壳 0.5.0 才有的主题令牌，本地对着外壳 `^0.5.0` 开发：

```json
{
  "devDependencies": { "@godcreator/gwb-shell": "^0.5.0" },
  "gwb": {
    "testedKernel": "0.2.7",
    "requires": { "@godcreator/gwb-shell": "0.5.0" }
  }
}
```

装进一个外壳还是 0.4.3 的 home，`plugin-manager.list` 里这个包带着：

```json
{
  "requires": { "@godcreator/gwb-shell": "0.5.0" },
  "unmetRequires": [{ "pkg": "@godcreator/gwb-shell", "required": "0.5.0", "installed": "0.4.3" }]
}
```

处理办法是升级被要求的那个包：`plugin-manager.update-all {"only":["@godcreator/gwb-shell"]}`。

## 为什么

插件的依赖规矩是 peer 只写 `cordis`、别的插件只写 dev（见[依赖怎么写](/docs/rules/deps)），dev 只管本地开发，管不到 home 里装的版本。用清单字段声明、发版时查写法、运行时由插件管理报告，是 `gwb.testedKernel`（见[在哪个内核上测过](/docs/rules/tested-kernel)）已经在用的做法。为什么不写成 peer、不让插件在运行时自己查、不给令牌写默认值，见轨迹卡[要求别的插件的最低版本：清单字段加报告](/trajectory/2026-09-24-requires-field-and-report)。
