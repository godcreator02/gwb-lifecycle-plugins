# 写插件的规矩

**本页回答**：写一个 gwb 插件要守哪些规矩；每条由哪道检查把关；哪些规矩现在只能靠人，哪些检查查的还是旧规矩。

规矩对新写的插件和这次改到的插件都生效。每条的做法、理由和例子在分页里，本页只列总表。

两件事不在这一组页里：

- **版本号升哪一位**：照说明书 `gwb-release`（`skill.read {"name":"gwb-release"}`），全生态一套
- **一件事该进内核还是做成插件**：判据在内核仓文档站的「关键设计」页——只有第一个插件运行之前必须完成的事才进内核，其余一律做成插件

写一个新插件，先读[依赖怎么写](/docs/rules/deps)和[cordis 服务怎么提供和使用](/docs/rules/services)，再读[卸载清理](/docs/rules/dispose)；要和别的插件打交道时读[插件之间怎么交互](/docs/rules/interaction)；带界面的读[页面代码与 importmap](/docs/rules/importmap)；发版之前读[在哪个内核上测过](/docs/rules/tested-kernel)。

## 把关的检查

| 检查 | 什么时候跑 | 没过会怎样 |
| --- | --- | --- |
| `devkit.release` 的发版前检查 | 构建之后、发第一个包之前 | 一个包都不发，回执按包列全 |
| `devkit.audit-deps` | 手动调，扫一个容器根下的各仓 | 只报告，不拦 |
| `devkit.audit-structure` | 手动调，查一个仓或全生态 | 只报告，不拦 |
| repo-kit 的两份测试守卫 | 各仓 `pnpm check` | 测试红 |
| 模板带的产物测试 | 构建之后跑 `pnpm check`（没有 `dist/` 时整组跳过） | 测试红 |

repo-kit 指 `@godcreator/gwb-repo-kit`：插件守卫查插件名与包名对得上、`apply` 时注册了窗格和命令，自述守卫查 `description` 的三项、`gwb.provides` 与源码对得上、说明书个数。模板带的产物测试是 `devkit.scaffold` 生成进每个插件的 `tests/artifact.test.ts`。

## 总表

| 规矩 | 做法见 | 把关 | 现状 |
| --- | --- | --- | --- |
| peer 只写宿主提供、构建产物里按值 import 的 `cordis`，其余写 dev | [依赖](/docs/rules/deps) | 没有工具检查 | **检查还按旧规矩**：`devkit.release` 对写成 peer 的 `@godcreator` 包要求写 `^<dev 下限>`、下限等于 dev 下限，写对了就放行，不会因为 peer 写了别的插件而拒；`devkit.audit-deps` 的 `peer-not-caret`、`floor-mismatch`、`floor-no-mirror`、`floor-unverifiable` 四类也按旧规矩报 |
| `cordis` 不写进 `dependencies` | [依赖](/docs/rules/deps) | `devkit.audit-structure`（`cordis-in-dependencies`，error） | — |
| `@godcreator` 包的 dev 写 `^` 范围或精确号，范围包含源上最新的正式版 | [依赖](/docs/rules/deps) | `devkit.release` 拒写法认不出、下限比源上 latest 新、latest 已出范围；`devkit.audit-deps` 报 `dead-pin`、`behind`、`out-of-range`、`loose-dev-pin` | — |
| 构建产物里的包名 import 只能是 node 内置模块、`electron`、`cordis` 与 importmap 里的名字 | [依赖](/docs/rules/deps) | 模板带的产物测试，只查 node 侧 | **检查还按旧规矩**：node 侧只放行词汇表包 `@godcreator/gwb-plugin-api`（它是纯类型包，按新规矩构建产物里不该出现它），`cordis` 不在放行名单里；浏览器侧不查；`devkit.release` 不查 |
| 类型引用到的包由使用方在 dev 里列全，`skipLibCheck: false` 下类型检查通过 | [依赖](/docs/rules/deps) | 没有工具检查 | — |
| 只引类型写 `import type`，不写 `import { type X }` | [依赖](/docs/rules/deps) | 没有工具检查 | — |
| 源码里不指回别的仓：没有 tsconfig `paths`、`link:` / `file:` 依赖 | [依赖](/docs/rules/deps) | `devkit.audit-structure`（`tsconfig-paths`、`local-protocol-dep`，error） | 跨仓的 `workspace:` 不查 |
| node 侧用 tsc 直接输出时，相对 import 带 `.js` | [依赖](/docs/rules/deps) | 模板带的产物测试 | — |
| 留着 `prepublishOnly: pnpm build`，`files` 白名单列全 | [依赖](/docs/rules/deps) | `devkit.audit-structure`（`prepublish-only`、`files-whitelist`，error）；`devkit.release` 照 `files` 验构建产物在不在 | — |
| importmap 只放整个页面必须只有一份的运行时代码，提供方只能是插件 | [importmap](/docs/rules/importmap) | 一个包名有两个提供方时，内核计算 importmap 时全部拒绝；「只放单例」「提供方是插件」没有工具检查 | — |
| 外置名单只从提供方读，不手抄 | [importmap](/docs/rules/importmap) | 没有工具检查 | 模板的 `build.ts` 还在手抄 react 的四个包名 |
| 扩展点服务继承 cordis 的 `Service`，注册随调用方卸载自动撤销 | [服务](/docs/rules/services) | 没有工具检查 | 命令总线 `gwbCommands` 还是 `ctx.provide` 提供的普通对象，注册命令仍要自己包 `ctx.effect` |
| 扩展点用服务，数据读写和动作用命令，同一能力只提供一种调用方式 | [服务](/docs/rules/services) | 没有工具检查 | — |
| 命令的 `plugin` 写包名，描述里写出参数形状，无参数写「无参数」 | [服务](/docs/rules/services) | repo-kit 插件守卫，只查模板那条 `<短名>.ping` | — |
| `gwb.provides` 的键与源码提供的服务名一一对应，`summary`、`usage` 不空 | [服务](/docs/rules/services) | repo-kit 自述守卫 | — |
| `gwbKernel` 用 `requireKernel` 取、不写进 `inject`；不写 `instanceof Service`；类的私有字段用 TS `private` | [服务](/docs/rules/services) | 没有工具检查 | — |
| 插件之间只通过服务和命令交互，不 import 别的插件 | [交互](/docs/rules/interaction) | 没有工具检查 | — |
| 共享磁盘数据格式或命令结构时，按区间比对契约版本，区间外拒绝加载 | [交互](/docs/rules/interaction) | 没有工具检查 | — |
| 谁提供接口谁定义类型；调用方不手写、不用 `as` 强转成提供方的类型 | [交互](/docs/rules/interaction) | 没有工具检查 | — |
| 插件的数据目录只由它自己读写 | [交互](/docs/rules/interaction) | 没有工具检查 | — |
| 自己启动或创建的一切，卸载时清理掉，并返回 promise | [卸载清理](/docs/rules/dispose) | 没有工具检查 | — |
| 插件包写 `gwb.testedKernel`，和运行中的内核在同一条版本线上 | [测过的内核](/docs/rules/tested-kernel) | `devkit.release` 拒没写、写的不是版本号、不在同一条版本线；`plugin-manager.list` 按包报 `kernelUntested` | — |
| 0.x 里只在破坏契约时升 x，其余升 y；0.0.x 先升到 0.1.0；同一个号不重发 | 说明书 `gwb-release` | `devkit.release` 拒 0.0.x 与源上已有的号；升哪一位没有工具检查 | — |

## 这个仓自己还没照做的

插件管理（`plugins/plugin-manager/`）按上面的规矩写：清单里没有 peer，服务只表示「插件管理装了」，上面没有方法。devkit 插件和它的模板还有几处是旧写法，各页「还没照做的」一节引了对应的代码：

- 模板的 `package.json.tpl` 把词汇表包、`gwb-commands`、`gwb-shell` 和已经不再发新版的 `gwb-tokens`、`gwb-shared-react` 写成了 peer
- 模板的 `build.ts.tpl` 手抄外置名单，`styles.css.tpl` 从 `gwb-tokens` 引 `theme.reference.css`，产物测试按旧规矩放行词汇表包
- devkit 自己的清单把词汇表包和 `gwb-shell` 写成 peer
