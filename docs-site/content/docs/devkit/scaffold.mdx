**本页回答**：`devkit.scaffold` 与 `devkit.scaffold.plugin` 从收到参数到回执之间做了什么、哪几步不能换顺序；模板分几部分、有哪些占位符、`title` 怎么编码；建文档站为什么不在本包里做、插件页为什么要在站装好之后才写；改模板要守什么、怎么测。写新插件的整条流程在说明书 `gwb-devkit` 的「新写一个插件」，本页不复述。

## 管什么

一个短名派生出一组名字：包名 `<scope>/gwb-<短名>`、插件名 `gwb-<短名>`、命令名 `<短名>.<动作>` 的前半。包的身份就是 `package.json` 的 `name`，发到哪里就是 `publishConfig.registry`：`scope` 参数定包名范围（缺省 `@godcreator`），`registry` 参数写进插件包的 `publishConfig.registry`（缺省团队源），`devkit.release` 照它发。这部分代码把包内模板按这组名字渲染好、写进一个还不存在的目录，再把这次建仓特有的下一步放进回执。

**仓的布局只有一种：workspace 仓。** 仓根是一个不发布的 private 包（`pnpm build` / `pnpm check` 递归到各成员，自己没有代码），插件放在 `plugins/<短名>/`，不是插件的包放在 `packages/`（按需）。只有一个插件的仓就是 `plugins/` 下恰好一个目录；加第二个插件是 `devkit.scaffold.plugin` 再生成一个，两条命令用的是同一份插件包模板，生成的格式一致。`devkit.scaffold.plugin` 只收 `pnpm-workspace.yaml` 的 `packages` 里有 `plugins/*` 的仓，别的当场拒。

<Diagram name="dk-scaffold" title="devkit.scaffold 建仓的七步：前三步在本包里，第 4、5 步经命令总线交给别的插件">
- 第 1 步 `planScaffold` 算计划：校验短名、`title`、`scope` 与 `registry`，派生包名与插件名，peer 里内核包的范围取运行中内核版本号的 x.y.z 三段；不碰磁盘
- 第 2 步在内存里渲染 `template/repo/`、`template/pkg/` 与插件页，`title` 按所在文件编码；认不出的占位符当场抛错
- 第 3 步 `writeRepo` 写磁盘：目标目录必须还不存在
- 第 4 步经命令总线调站点插件的 `docs-site.create` 生成 `docs-site/` 的初始站点（回执 `docs.built`）；第 5 步紧接着调 docfirst 插件的 `docfirst.attach` 装六区（回执 `docs.attached`）。这两步画成虚线框：哪个插件没装就跳过，建仓不算失败
- 第 6 步：`docs-site/docfirst.config.mjs` 在，才写插件页 `docs-site/content/docs/plugins/<短名>.mdx`
- 第 7 步回执：`nextSteps` 只写这次建仓特有的——仓与插件包在哪、站建到了哪一步与端口，流程指向说明书 `gwb-devkit`
</Diagram>

建文档站是两步，两步都不是本包的命令，顺序不能反、中间不能插别的事：`docfirst.attach` 只在还没写过内容的初始站点上装得了（这条由它自己检查），所以两步紧挨着做，插件页要等六区装好之后才写。加插件不建站：整个仓一个站，仓里已有装好六区的站时只往现状区加这个插件的插件页。

## 不知道什么

`scaffold.ts` 里的函数不知道 fumadocs、不知道代码引用怎么核对、也不知道命令总线存在——它们连 `ctx` 都拿不到，建站由 `src/index.ts` 的 `buildDocsSite` 经命令总线发出去。**连「站建成没有」都是调用方告诉它的**：`nextSteps` 收一个 `site` 参数，按实际结果分支，不按调用方想不想建站分支。

也不知道生成的仓将来怎么发版：发版的做法在说明书 `gwb-release` 里，生成的 README 与回执都只指向它。README 里插件清单的更新由写文档的人做，`nextStepsPlugin` 最后一步提醒。

## 数据结构

两条流程：建仓（参数 `ScaffoldInput` → 计划 `ScaffoldPlan` → 渲染好的 `RenderedFile[]`）、加插件（`ScaffoldPluginInput` → `ScaffoldPluginPlan` → 同样的 `RenderedFile[]`）。计划算出来之后，后面每一步只看计划，不再回头看参数。

{/* ref file="../plugins/devkit/src/scaffold.ts" lines="42-112" */}

两种参数里的 `kernelVersion` 不是命令参数：`src/index.ts` 从运行中的内核服务取 `gwbKernel.version` 传进来，计划里只留 x.y.z 三段（开发版内核去掉预发布段），渲染成生成的 `package.json` peer 里内核包的范围 `^x.y.z`。

**模板**在包根 `template/`，每个文件都带 `.tpl` 后缀（写到磁盘时去掉），都属于三部分之一：`repo/` 生成仓根，`pkg/` 生成 `plugins/<短名>/`（插件包，建仓与加插件共用的唯一正本），`site/plugin.mdx.tpl` 生成文档站现状区里的插件页。

{/* tree dir="../plugins/devkit/template" depth="4" */}

占位符八个：`{{name}}`、`{{title}}`、`{{pkg}}`、`{{registry}}`、`{{pkgName}}`、`{{cssPrefix}}`、`{{kernelVersion}}`、`{{docsBlock}}`。`{{docsBlock}}` 只有仓根 README 用，是按「建不建站」写好的一段话；加插件与插件页用前七个：

{/* ref file="../plugins/devkit/src/scaffold.ts" lines="301-318" */}

模板里几处要守的写法：

- **一律带 `.tpl` 后缀**：`npm pack` 固定不打包 `.gitignore`，统一加后缀，一条规则管住全部文件
- **`.oxlintrc.json` 放在插件包里、不放仓根**：oxlint 按工作目录找配置，插件包自带配置，搬到哪个仓都不用改
- **`pnpm-workspace.yaml` 里的 `allowBuilds` 放行 esbuild 的安装脚本**：pnpm 11 起这项设置只读这个文件；不放行时 install 报「Ignored build scripts」、之后的 `pnpm run` 连锁失败，调用栈看不出原因
- **带 `oxlint-tsgolint`**：`oxlint` 需要类型信息的规则要用它，少了 `pnpm lint` 报「Failed to find tsgolint executable」；它与 `oxlint` 都写准确版本号
- **`@godcreator` 包的版本号跟着源走**：peer 里的内核包与两个插件（命令总线、外壳）写 `^<版本>`，要和源上 `dist-tags.latest` 在同一条线；不在同一条线，新仓第一次发版就被发版前检查拦下；写了源上没有的版本，新仓 `pnpm install` 直接失败。改之前先 `pnpm view <包> dist-tags.latest`

## 提供的接口

对外两条命令：`devkit.scaffold { name, dir, title?, docs?, scope?, registry? }` 与 `devkit.scaffold.plugin { name, repo, title?, scope?, registry? }`。两条的回执都带 `pkg`（完整包名）、`registry`（写进 `publishConfig.registry` 的发布目标）、`pluginPage`（写下的插件页的绝对路径，没写时是 `null`）与 `nextSteps`；建仓的回执另带 `docs`。**参数不对时把整份用法放进报错**：命令总线不带参数形状，agent 能不能看出自己错在哪全靠这段话。文档站的端口不是参数：由站点插件自己选，回执 `docs.port` 从它的回执里取。

## 依赖的接口

| 接口 | 用来做什么 | 生产实现 | 测试实现 |
| --- | --- | --- | --- |
| `node:fs` | 读包内模板、检查仓的布局、写渲染好的文件 | 直接调用，不注入 | 不替换，真写临时目录 |
| 包内 `template/` | 初始文件的正本；`packageRoot` 从本模块所在目录向上找 `package.json` 定位，找到盘根都没有就抛 | 发布出去的包里那份（`files` 里有 `template`） | 同一份 |

## 怎么单独测

给一份参数，看抛什么、算出什么；给一个临时目录，看磁盘上写下了什么。整个过程不启动进程、不开窗口，`tests/scaffold.test.ts` 测：短名、范围、地址的校验与缺省值；给了 `scope`、`registry` 时包名、`publishConfig.registry`、README、插件页与回执跟着变；加插件对不是 workspace 仓的拒绝与 YAML 各种写法；正反斜杠得到同一个路径；`docsBlock` 与 `nextSteps` 各种情况写了什么；生成的清单 peer 里有内核包 `^<运行命令的内核版本号>` 且过得了发版前检查的比对；认不出的占位符真的抛错；每个模板文件都声明了属于哪部分；在临时 workspace 仓里真的生成一个 `plugins/<短名>/`；目标已存在时拒绝。

`title` 那几条用一个凑齐了引号、反斜杠、`{}`、`<>`、Markdown 标点、`${y}`、`*/` 的 title 渲染整套模板，再用真的解析器与编译器读生成的文件：JSON 用 `JSON.parse`，YAML 与 frontmatter 用 yaml 库，node 侧入口与浏览器侧窗格用 esbuild 编成 CommonJS 后执行，README 与插件页用 MDX 编译器（带 GFM 表格）渲染。生成的 JSON、YAML 与 frontmatter 读不读得懂也由这里核对，运行时不再读一遍：模板只有本包这一份。

{/* has file="../plugins/devkit/tests/scaffold.test.ts" text="生成的插件包 peer 里写了内核包 ^<运行命令的内核版本号>：建仓与加插件都一样，发版前检查认" */}

`tests/commands.test.ts` 在假上下文上调两条命令，测站点插件装没装、建站两步成没成时的回执。

生成的仓在真实的 pnpm 里能不能 install / build / check，单元测试回答不了：`probes/2609191042_workspace-scaffold/` 用构建产物真的生成了一个仓跑完三步，`probes/2609251020_scaffold-hostile-title/` 用同样的办法生成一个 title 带各种特殊字符、`dir` 用正斜杠写的仓。

## 代码地图

**在哪**：纯逻辑全在 `src/scaffold.ts`；命令登记与建文档站在 `src/index.ts` 的 `registerScaffoldCommand`、`registerScaffoldPluginCommand` 与 `buildDocsSite`；初始文件的正本在包根 `template/`。

**先读** `planScaffold`：建仓的入口与全部校验；加插件从 `planScaffoldPlugin` 读起。

**读序**：计划 → `placeholders` 与 `render` 把模板变成内存里的文件表（`titleEncoderFor` 决定 `title` 怎么编码）→ `landRel` 决定各部分写到哪 → `writeRepo` 写磁盘 → `nextSteps` / `nextStepsPlugin`。建文档站在这之后，由 `index.ts` 发出；站装好六区之后 `pluginPageTarget` 给出插件页的位置，`writePluginPage` 写下去。

**可跳过**：`template/` 下的 `.tpl` 是给别的仓的内容，要看模板长什么样就看那个目录本身，这一页不抄。
