**本页回答**：`devkit.audit-structure` 查什么、不查什么（分工比检查本身更要紧）、检查规则怎么保证跟模板一致。

## 管什么

模板只生成一种仓的布局之后，就要有东西告诉人：哪个仓离这个布局多远、旧布局仓照哪份清单迁、手工加出来的目录有没有让名字对不上。没有这条检查，「改到哪个就迁哪个」只是一句口号。

这条命令只读地回答这些。参数与 `devkit.audit-deps` 一样：给 `dir` 查一个仓；给 `root` 或什么都不给就扫全生态（退役单元与测试件跳过，用的是同一个 `collectRepos`）。

**findings 分三级**：error（构建不出来、装不上、一定出错）、warn（能用但偏离当前布局）、info（提示——旧布局仓收到一条按这个仓的实际文件名列好的迁移清单）。

## 不管什么

| 不管的 | 归谁 |
| --- | --- |
| 依赖的版本写法、peer 规矩 | `devkit.audit-deps` 与 `devkit.release` 的发版前检查 |
| `description` 的三项自述、服务名、说明书份数 | repo-kit 的自述守卫（在各仓的 tests 里） |
| 文档里的说法 | docfirst |
| 构建产物的形状 | 各仓的产物测试 |

同一条规矩多一处检查就多一处可能不一致。结构体检只管**布局与能静态判断的红线**：仓的布局、插件包是否自带全部配置、名字派生链、`files` 白名单、`prepublishOnly`，外加三条能从文件直接判断的红线（`cordis` 写在 dependencies、tsconfig 的 `paths` 有包内 `@/*` 以外的映射、`link:` / `file:` 依赖）。跨仓的 `workspace:` 依赖不查。

**不放进发版前检查**：发版前检查拦发版，这条是日常查看；warn 也拦发版的话，这个工具就没人用了。

## 扫描与规则

扫描只看三层目录的名字与几个关键文件（package.json、`src/index.ts`、tsconfig），不进 node_modules、不进 docs-site——查的是布局，不是内容：

判断「是不是 workspace 仓」用的正则跟 `devkit.scaffold.plugin` 收不收这个仓用的相同（`structure.ts` 的 `yamlHasPluginsZone` 与 `scaffold.ts` 的 `planScaffoldPlugin` 各写了一遍同一个正则），不会出现「加插件收了、体检却说不是 workspace 仓」。

旧布局仓不算错：布局照报，迁移清单照给——`git mv` 的文件清单按这个仓的实际条目现拼，不是一段通用的话。名字派生链的第三环（插件名 = `gwb-<短名>`）只查 `export const name` 形式的插件；**Service 形式**（`export default class … extends Service`，基础插件仓的数据插件那批）没有也不需要这个导出，第三环查不了，只查入口文件在不在——拿写法当判据只会误报。

## 规则与模板的一致：模板是唯一正本

检查规则与模板是同一件事的两份描述，放着不管一定会不一致。保证一致的是往返测试：`renderTemplate` / `renderPlugin` 生成的文件直接写进临时目录、扫描、检查，**断言零 findings**。模板的第三部分插件页（`template/site/plugin.mdx.tpl`）写进文档站，结构体检不进 `docs-site/`，所以往返测试不含它。模板改了布局而检查规则没跟上，测试当场失败；检查规则加了一条而模板生成的仓过不了，也当场失败——两边都不能单独改。

## 怎么单独测

`tests/structure.test.ts` 真写临时目录（扫描本来就读磁盘）：往返测试两条（建仓、加插件）；布局判断（旧布局仓收到 info 迁移清单、不是插件仓的不报、有 `plugins/` 目录而 `pnpm-workspace.yaml` 没那条的报 `shape-unknown`、workspace 仓根的三条 warn）；插件包每一类问题一条（名字派生链两环、目录用全名、插件放在 `packages/`、白名单、`prepublishOnly`、配置不全、有浏览器代码却缺构建配置）；静态红线（`cordis` 的位置、`paths` 非空才报、只有指向包内的 `@/*` 时放行、别的写法与解析不了的 tsconfig 照报、本地协议依赖）。

**在哪**：扫描与规则全在 `src/structure.ts`，命令登记在 `src/index.ts` 的 `devkit.audit-structure` 那段。
