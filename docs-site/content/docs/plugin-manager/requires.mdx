# 要求的插件版本

**本页回答**：插件怎么声明它要求 home 里别的包最低到哪个版本；`list` 回执里的 `requires`、`unmetRequires`、`requiresInvalid` 怎么算出来；「装了的版本」从哪读；为什么只报告、不拦加载。

## 插件在 package.json 里声明

**是什么**：插件包在 `package.json` 的 `gwb` 字段里写 `requires`，形状是 `{ "<包名>": "<最低版本号 x.y.z>" }`，意思是运行时 home 里这个包装的版本不低于这个号。可选，只写真用到了那个包某个版本才有的东西的包。什么时候该写、怎么写见规矩页[要求别的插件的最低版本](/docs/rules/requires)。

**为什么**：插件的 `peerDependencies` 只写 `cordis`，别的插件写在 dev 里，dev 只管本地开发。插件用到外壳新加的主题令牌时，home 里的外壳太旧也不报错，令牌取不到值，样式静默失效；有了这个声明，插件管理能把「装的版本不够新」报出来。

## list 回执里的三个字段

**是什么**：`list` 给每个包读它装在 home 里的 `package.json`，回执里多三个字段：

- `requires`：`gwb.requires` 原样照抄；没写、或写的不是「包名 → 字符串」的对象时没有这个字段
- `unmetRequires`：没满足的要求，每条是 `{ pkg, required, installed? }`。home 里装的版本低于 `required`、`required` 不是合法的 x.y.z、或者没装（这时没有 `installed` 字段），都列进来；全都满足、没写 `gwb.requires` 时是空数组
- `requiresInvalid`：`gwb.requires` 写了但不是「包名 → 字符串」的对象时，说明哪里不对；这时一条都不比对

**怎么比**：最低版本号只收 x.y.z；装的版本号逐段按数字比，三段相同时带预发布段的算更低——装的是 `0.5.0-dev.1` 不满足要求 `0.5.0`，装的是 `0.5.1-dev.1` 满足。

**「装了的版本」从哪读**：home 的 `node_modules/<包名>/package.json` 在，就算装了，版本取它的 `version`。`list` 本来就读 home 的 dependencies 与条目里每个包的清单；`gwb.requires` 点名了别的包时再补读一次。不合包名规则的键不拿去拼路径，按没装报。

## 只报告，不拦加载

**是什么**：`unmetRequires` 不空、`requiresInvalid` 有值的插件照常加载、照常能装能升，插件管理不拦它。

**为什么**：和 `kernelUntested` 同理（见[在哪个内核上测过](/docs/plugin-manager/kernel-compat#只报告不拦加载)）：要求没满足多半只是某处样式或某个新功能不对，整个插件拦下来反而没法用；看到报告，升级被要求的那个包就解决了。要保证声明写得对，在发版时检查。

## 发版前 devkit.release 检查写法

**是什么**：`devkit.release` 对写了 `gwb.requires` 的插件包查四条：是对象；每个值是合法的 x.y.z；每个包也写在 `devDependencies` 里；要求的版本不高于 dev 范围的下限（dev 写 `workspace:` 的不比）。有一条不对就一个包都不发。

**两份判法**：「合法的最低版本号」在 devkit 与插件管理里各有一份（`isMinimumVersion`），不跨包 import。devkit 的 `tests/requires-parity.test.ts` 拿同一组输入跑两份，发得出去的声明插件管理一定认得。
