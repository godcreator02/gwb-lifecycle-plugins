# 热升级

**本页回答**：怎么查出哪些包有新版本；为什么升级与重新加载必须在同一条命令里；升级计划按什么排；一次热升级从头到尾依次发生什么。重新加载一条条目的时序在[重新加载一条条目](/docs/plugin-manager/remount)。

热升级管 home 里的全部包，插件管理自己和命令插件也在其中：它们各是 `cordis.yml` 里的一条条目，和别的插件一样升级。

## 查新版本

**是什么**：`outdated` 运行一次 `pnpm outdated --json`，返回「包名 → `{ current, latest }`」，空对象表示全都最新。

**怎么做**：退出码 1 表示「有过期包」，是结果不是失败；找不到 pnpm、输出解析不了都转成 `ok: false` 的回执，界面上只显示一句提示。它只读不写，不经过 BUSY 检查，但 pnpm 照样排进串行队列（见[同一时刻只允许一个改动](/docs/plugin-manager/home#同一时刻只允许一个改动busy)）。

## 升级与重新加载在同一条命令里

**是什么**：`update-all` 一条命令做完：一次 `pnpm add` 把过期包升到精确版本 → 逐条重新加载 → 整页重新加载。只升某几个包也用它，给 `only`；没有「只升包、不重新加载」的命令。

**为什么**：pnpm 装新版本时会删掉旧版本目录。升级之后、重新加载之前只要隔着一条命令，旧版插件就在自己的目录已经删掉之后还运行一段，读自己的文件就读不到：

<Diagram name="pm-upgrade-gap" title="分两条命令时，旧版插件在目录删掉之后还要运行一段">
- 分两条命令：`pnpm add` 装上 A@1.1、删掉 A@1.0 的目录；到另一条命令停用再启用之前，旧版 A 还在运行，读自己的文件就读不到
- 同一条命令：`pnpm add` 一结束马上停用再启用，旧版 A 在目录删掉之后不再运行
</Diagram>

**例外**：命令本该保持原子、一条只做一件事，多步流程写进说明书由调用方一步步调。`update-all` 是允许的例外：升级与重新加载都依赖「这次升级之前磁盘上是哪个版本」，拆开就有上图那段空档。`pnpm add` 失败时一条条目都不动。

这一条只能实机验证：在隔离 home 里先装某个包的旧版本，再调 `plugin-manager.update-all`，看条目回到 `ACTIVE`、日志里没有读不到文件的报错。

## 升级计划

**是什么**：升哪些包、重新加载哪些条目、按什么顺序，由一个纯函数算出，单独测。

{/* ref file="../plugins/plugin-manager/src/update-all.ts" lines="44-57" */}

- **精确版本**：用 `outdated` 查到的版本号，不用 `@latest` 标签——两次查询之间又发了一版，也不会装成回执上没写的那个
- **每条条目各自重新加载**：被别的插件 inject 的插件重新加载时，cordis 会把依赖它的插件停用再启动，但那是重跑内存里的旧代码，磁盘上的新版本没有加载，所以不能指望这种连带
- 包按包名排，包内的条目按条目树里的先后；本来就停用的条目保持停用，记为 `skipped`
- **插件管理自己排最后**：它所在的包排在所有包之后，包内它那条条目也排最后
- 给了 `only` 就只升点名的几个；点了名却不在过期清单里的，回执的 `note` 里列出来

**守住它的测试**：计划是纯函数，每一条都有测试。

## 一次热升级依次发生什么

<Diagram name="pm-upgrade" title="一键热升级的时间线：每条横道是一个参与方，竖虚线是回执发出的时刻">
- 调用方调用 `update-all`；插件管理查过期包，定计划
- 插件管理一次 `pnpm add` 精确版本；磁盘上 A@1.0 的目录删掉、A@1.1 装上
- 条目 A 停用再启用，重新解析拿到 A@1.1，回到 `ACTIVE`
- 回执发出，调用方收到 `selfDeferred: true`、`reload: deferred`
- 下一个宏任务里重新加载插件管理自己，拿到新版本
- 外壳 `shell.reload` 整页重新加载，窗格拿到新版本的页面代码
</Diagram>

**插件管理自己在回执之后**：升级清单里有插件管理自己时，它那条条目在回执发出之后才重新加载，回执里 `selfDeferred` 是 `true`，它的条目 `action` 是 `deferred`。理由与[重新加载插件管理自己](/docs/plugin-manager/remount#目标是插件管理自己先回执后重新加载)相同。

{/* ref file="../plugins/plugin-manager/src/index.ts" lines="499-514" */}

**整页重新加载**：经命令插件调用外壳的 `shell.reload`，按命令名查找，不 import 外壳。回执的 `reload`：`done` 已经重新加载；`deferred` 等插件管理自己重新加载完再执行；`unavailable` 命令表里没有它或它失败了，界面要手动刷新，原因在 `note` 里。

{/* ref file="../plugins/plugin-manager/src/index.ts" lines="118-137" */}

**升到 MCP 入口自己**：`gwb-mcp` 重新加载时，进行中的 MCP 请求会中断，agent 要重连一次，再用 `plugin-manager.list` 核对版本与 `active`。
