# 升内核

**本页回答**：内核包怎么换、`cordis` 怎么跟着对齐；为什么内核包与 `cordis` 热升级不了、为什么只有 `update` 的 `specs` 这一条路；回执多了哪两个字段；哪几种失败、各自 home 停在什么状态。

## 内核包写进 specs

内核包 `@godcreator/gwb-kernel-desktop` 经 `update` 的 `specs` 换：升到最新写 `{"specs":{"@godcreator/gwb-kernel-desktop":"latest"}}`，也可以给版本号或 `file:<绝对路径>`，还可以连同别的包一起写。`specs` 里有内核包时，插件管理依次做：

1. 一次 `pnpm add` 装上 `specs` 里的全部包（清单写 `^` 范围），照[热升级](/docs/plugin-manager/upgrade#specs-装完核对版本号)的规则核对准确版本号
2. 读 home 里装上的内核包的 `package.json`，取它 `peerDependencies.cordis` 写的精确版本号
3. `pnpm add --save-exact cordis@<那个版本>`，装完读回核对 `cordis` 装上的就是它
4. **不重新加载任何条目**：`updated` 每项的 `entries` 是空数组，末尾多一项插件管理自己对齐的 `cordis`；`dependents` 是空数组

`outdated` 不报内核有没有新版本；写 `latest` 就装源上的最新版，回执里内核包的 `from` 与 `to` 相同就是已是最新。

只有这一条路：devkit 开发内核时要把内核开发版与插件开发版一次装完、再重启那个 home；升内核另有一条命令的话，两条命令先后怎么排都不对（见轨迹卡[升内核并进 specs](/trajectory/2026-09-25-kernel-via-specs-caller-reloads)）。

## 为什么热升级不了

内核在主进程里运行，停用再启用条目换不掉它；home 根上的 `cordis` 是内核与所有插件共用的那一份，都已经 import 了它，换了也要重启才生效。所以这两个包由内核决定版本：`list` 与 `outdated` 不列它们，`update` 的 `only` 点了它们直接报错，`uninstall` 也不许卸（卸掉 home 就启动不了）。

## cordis 由插件管理对齐

内核包把 `cordis` 写成 peer，pnpm 把它解析到 home 根上的那一份；home 根上的版本和内核包要的不同，内核就运行在它没验过的 `cordis` 上。该装哪个版本只有装上的内核包自己知道（`latest` 与 `file:` 写法事先看不出），所以 `specs` 里不许写 `cordis`，写了直接报错。内核包 peer 里的 `cordis` 必须是精确版本号：写成范围就说不清 home 根上该装哪一个，这时不装 `cordis`、回 `ok: false`。

## 回执多出的两个字段

- **`restartRequired`**：装上的内核版本和正在运行的不同时是 `true`，`note` 说重启工作台后才生效、重启由人决定；装上的就是正在运行的那一版时是 `false`
- **`pluginsOutsideRange`**：home 里 `keywords` 含 `gwb-plugin`、peer 里内核包的范围不包含新内核（或没写范围）的插件，按包名排。用的就是 `list` 算 `kernelUntested` 的那个函数（见[内核兼容性](/docs/plugin-manager/kernel-compat)），同样只报告：重启后它们照常加载，要不要先升它们由人决定

## 失败时 home 停在哪

| 在哪一步失败 | 回执 | home 的状态 |
| --- | --- | --- |
| 第一次 `pnpm add` | `ok: false`，`error` 带 pnpm 输出的最后几行 | 没改 |
| 装上的内核包不是 `specs` 里写的准确版本号 | `ok: false`，`error` 说先别重启 | 内核包换了，`cordis` 没动 |
| peer 里的 `cordis` 不是精确版本号、装 `cordis` 时 pnpm 失败、装上的 `cordis` 不是要的版本 | `ok: false`，`data.kernel` 是已经装上的内核版本 `{ from?, to }`，`error` 说 `cordis` 没对齐、先别重启 | 内核包换了，`cordis` 没对齐 |

后两种时重启，新内核会运行在没对齐的 `cordis` 上；照 `error` 修好再调一次。
