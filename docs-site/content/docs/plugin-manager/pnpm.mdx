# pnpm

**本页回答**：插件管理用的是哪个 pnpm、怎么找到它；怎么启动它、带什么参数与环境、读回什么；卸载时正在运行的 pnpm 为什么不结束。pnpm 什么时候运行、为什么排队，见[只有插件管理写 home](/docs/plugin-manager/home#包只经-applytohome排进一个串行队列)。

## 只认两个固定位置的 pnpm

**是什么**：pnpm 由用户照 `INSTALL.md` 装好，插件管理不自带。每次要运行 pnpm 时按顺序检查两个位置，第一个存在的文件作数：

1. `%LOCALAPPDATA%\pnpm\bin\pnpm.exe`：pnpm 12 官方安装脚本的默认位置
2. `%APPDATA%\npm\node_modules\pnpm\pnpm.exe`：`npm i -g pnpm` 装的 pnpm 12 包里的原生可执行文件，PATH 上的 `pnpm.cmd` 转去调用的就是它

{/* ref file="../plugins/plugin-manager/src/pnpm-location.ts" lines="22-28" */}

找到之后运行一次 `--version` 核对版本：主版本号要是 12，并且不低于 12.4.2。两个位置都没有、`--version` 运行失败、版本不对，一律报错，报错里写明检查的是哪个路径、该装哪个版本；**不去试另一个位置，也不找 PATH、不读设置、不读 `PNPM_HOME`**。devkit 用的是同一套规则，两个插件各存一份 `src/pnpm-location.ts`、逐字相同，由 devkit 的 `tests/pnpm-location-parity.test.ts` 对照。

{/* ref file="../plugins/plugin-manager/src/pnpm-location.ts" lines="7-8" */}

**为什么**：

- 装机、插件管理、devkit 用的是同一个 pnpm：第一次装 home 时插件管理还不在，只能用机器上的 pnpm，自带一份就会有两个版本改同一个 home
- 只认固定位置、不看 PATH：PATH 上排在前面的是哪一份，每台机器都不一样；两个位置都是原生可执行文件，可以直接启动，不用开 shell，也就没有参数引号转义的问题
- 核对版本：pnpm 大版本之间 `node_modules` 的布局与输出格式会变，版本不对就当场报错，不带着错的版本改 home

**守住它的测试**：两个位置的顺序、第一个存在的作数、版本不对不去试第二个、`--version` 失败与环境变量缺失都报错；包清单里没有 `dependencies`。

## 参数、环境与读回什么

**命令行参数与工作目录**：改 home 只有 `add <spec…>` 与 `remove <包名>` 两种，都经 `applyToHome` 排进同一个串行队列；只读的是 `outdated --json`。工作目录一律是 home。

{/* ref file="../plugins/plugin-manager/src/index.ts" lines="826-829" */}

**环境**：原样传下去，用户的 `~/.npmrc`、pnpm 配置（`@godcreator` 的包源、包龄豁免）照常读到；只去掉 `ELECTRON_RUN_AS_NODE`——它只对 electron 有意义，留着会传给 pnpm 启动的依赖构建脚本。直接启动这个文件，不开 shell。

{/* ref file="../plugins/plugin-manager/src/pnpm-path.ts" lines="7-12" */}

**不设超时**：装一个大包本来就可能要几分钟，定一个时限只会在慢网络上错误地结束正常的安装；网络层的超时 pnpm 自己有。真卡住了，由人去结束进程。

**读回什么**：`add` / `remove` 只看退出码，0 是成功；成功时不保留输出（几十行进度没人看），失败时回执带 stdout 与 stderr 合起来的最后 12 行，pnpm 把原因写在最后。`outdated` 要读 stdout 上的 JSON，另用 `runPnpmCapture` 完整保留 stdout；退出码 1 表示「有过期的包」，是结果不是失败。两种运行方式对输出的取舍相反，所以是两个函数，不合成一个。

{/* ref file="../plugins/plugin-manager/src/pnpm.ts" lines="10-25" */}

pnpm 升大版本时输出格式可能变，`outdated` 解析不了就回失败，原因里说明这一点。

**守住它的测试**：启动参数与环境、输出只留最后几行有单元测试；启动进程、收集输出、读退出码用 node 代替 pnpm 可执行文件来测；真的 pnpm 装包只能实机验证（`devkit.dev` 装进隔离 home 后调 `plugin-manager.install` / `outdated`）。

## 卸载时不结束 pnpm

**是什么**：插件管理卸载时（包括内核退出、插件管理被重新加载），正在运行的 pnpm 不结束，让它运行完。

**为什么**：pnpm 正在改 home 的 `package.json` 与 `node_modules`，中途结束会留下装了一半的 home，比让它运行完更难收拾；它运行完之后回执没人接收，改动照样生效。
