# pnpm

**本页回答**：插件管理用的是哪个 pnpm、怎么找到它；怎么启动它、带什么参数与环境、读回什么；卸载时正在运行的 pnpm 为什么不结束。pnpm 什么时候写 home 见[包：只经 applyToHome](/docs/plugin-manager/home#包只经-applytohome)，为什么同一时刻最多一个写 home 的 pnpm 见[同一时刻只允许一个改动](/docs/plugin-manager/busy)。

## 只认两个固定位置的 pnpm

pnpm 由用户装好，插件管理不自带。每次要运行 pnpm 时按顺序检查两个位置，第一个存在的文件作数：

1. `%LOCALAPPDATA%\pnpm\bin\pnpm.exe`：pnpm 12 官方安装脚本的默认位置
2. `%APPDATA%\npm\node_modules\pnpm\pnpm.exe`：`npm i -g pnpm` 装的 pnpm 12 包里的原生可执行文件，PATH 上的 `pnpm.cmd` 转去调用的就是它

找到之后运行一次 `--version`（最多等 30 秒）核对版本：主版本号要是 12，并且不低于 12.4.2。两个位置都没有、`--version` 运行失败、版本不对、不是 Windows、`LOCALAPPDATA` 或 `APPDATA` 不在，一律报错，报错里写明检查的是哪个路径、该怎么装；**不去试另一个位置，也不找 PATH、不读设置、不读 `PNPM_HOME`**。

- **同一个 pnpm**：安装工作台、插件管理、devkit 用的是同一个。第一次装 home 时插件管理还不在，只能用机器上的 pnpm，插件管理自带一份就会有两个版本改同一个 home（见轨迹卡[插件管理不再自带 pnpm](/trajectory/2026-09-24-pnpm-two-fixed-locations)）。devkit 从插件管理的主入口 import `locatePnpm`，规则只有这一份（见[主入口给 devkit 的导出](/docs/plugin-manager#主入口给-devkit-的导出)）
- **只认固定位置、不看 PATH**：PATH 上排在前面的是哪一份，每台机器都不一样；两个位置都是原生可执行文件，可以直接启动，不用开 shell，也就没有参数引号转义的问题
- **核对版本**：pnpm 大版本之间 `node_modules` 的布局与输出格式会变，版本不对就当场报错，不带着错的版本改 home

## 参数、环境与读回什么

**命令行参数与工作目录**：写 home 只有 `add <spec…> --save-exact` 与 `remove <包名>` 两种，都经 `applyToHome` 运行；只读的是 `outdated --json`。工作目录一律是 home。参数以数组传给进程，不经 shell。

{/* ref file="../plugins/plugin-manager/src/index.ts" lines="765-768" */}

**环境**：原样传下去，用户的 `~/.npmrc`、pnpm 配置（`@godcreator` 的包源、包龄豁免）照常读到；改两处。去掉 `ELECTRON_RUN_AS_NODE`：它只对 electron 有意义，留着会传给 pnpm 启动的依赖构建脚本。设 `pnpm_config_auto_install_peers=false`：插件的 peer 写了别的插件、home 里没装那个插件时，pnpm 默认把它自动装进 `node_modules/.pnpm`，不写进 home 的 `package.json`、没有条目，插件管理也不认它；命令行参数 `--config.auto-install-peers=false` 会被 pnpm 忽略，只有环境变量或 home 的 `pnpm-workspace.yaml` 关得掉（见 [peer 满没满足](/docs/plugin-manager/peers#缺的-peer-不会被自动装上)）。

**不设超时**：装一个大包本来就可能要几分钟，定一个时限只会在慢网络上错误地结束正常的安装；网络层的超时 pnpm 自己有。真卡住了，由人去结束进程。

**读回什么**：`add` / `remove` 只看退出码，0 是成功；成功时不保留输出，失败时回执 `error` 末尾带 stdout 与 stderr 合起来的最后 12 行，pnpm 把原因写在最后。进程没启动成功也不抛，退出码记为 `null`，原因在那几行里。`outdated` 要读 stdout 上的 JSON，另用 `runPnpmCapture` 完整保留 stdout，退出码 1 表示「有过期的包」，是结果不是失败；pnpm 升大版本时输出格式可能变，解析不了就回失败，原因里说明这一点。两种运行方式对输出的取舍相反，所以是两个函数。

## 卸载时不结束 pnpm

插件管理卸载时（包括内核退出、插件管理被重新加载），正在运行的 pnpm 不结束，让它运行完。pnpm 正在改 home 的 `package.json` 与 `node_modules`，中途结束会留下装了一半的 home，比让它运行完更难收拾；它运行完之后回执没人接收，改动照样生效。
