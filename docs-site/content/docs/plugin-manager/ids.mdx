# id 与归属

**本页回答**：条目 id 是什么、为什么不能改；装包时 id 怎么选、为什么要看磁盘上的归属记录；插件改了包名怎么接着用旧数据。

## id 是身份，一经确定不改

**是什么**：每条条目有一个 id，写在 `cordis.yml` 里。数据插件、设置插件都按 id 给这条条目分目录、分区。

**为什么不能改**：改了 id，原来的设置与数据就留在旧分区里，再也读不到。所以插件管理没有改 id 的命令。界面上给人看的名字是插件自己报给外壳的名字（外壳的 `shell.plugins` 命令），插件管理不存显示名。

**怎么做**：

- 字符集是 kebab-case：小写字母、数字、单个连字符分段。数据插件与设置插件用同一套字符集校验，三处必须一起改——生成的 id 通不过它们的校验，这条条目就存不下任何设置和数据
- 默认 id 是包名去掉 scope 与 `gwb-` 前缀：`@godcreator/gwb-py-cli` → `py-cli`；重名时加数字后缀 `py-cli-2`
- 一定显式给 loader 传 id：不给的话 loader 每次启动生成一个新的随机 id，设置与数据每启动一次就新建一份

## 选 id 时看磁盘上的归属记录

**是什么**：数据插件、设置插件都记录了每个 id 属于哪个包，删了条目也还在。插件管理选 id（`install`、不给 id 的 `add-entry`）时把这份记录和条目树一起看。

**为什么**：默认 id 去掉了 scope，`@a/gwb-foo` 和 `@b/foo` 都叫 `foo`；而删掉条目后，它的数据与设置还留在磁盘上。只按条目树判断重名，空出来的 `foo` 会被下一个同名的包拿走，读到前一个包的数据。

**怎么做**：

- 先沿用：磁盘上属于本包、条目树上又空着的 id，说明这个包装过又卸了，沿用它，数据与设置原样接上
- 否则从默认 id 起加后缀，条目树上已有的和属于别的包的都跳过
- 手动给的 id（`add-entry` 带 `id`）在条目树上已被占用、或属于别的包，直接拒绝，错误里写明属于谁

## 转归属：transfer-owner

**是什么**：同一个插件改了包名、要继续用旧数据时，用 `transfer-owner`（`{ id, pkg }`）把这个 id 的数据目录与设置分区一起转给新包名，再 `remount` 那条条目。

**为什么**：归属记录拦住的是「别的包读到这份数据」；包改名以后，新包名在记录里也是「别的包」，要人确认是同一个插件，才能放行。

**怎么做**：数据目录、设置分区归数据插件、设置插件管，插件管理不自己拼路径去碰它们，只调这两个插件的服务 `owners` / `transferOwner`。这两个插件都是可选的，用局部注入接上；哪个没装，回执里对应的那一项是 `false`。

{/* ref file="../plugins/plugin-manager/src/index.ts" lines="746-757" */}

<Note>
**不是同一个插件，别转归属**：那等于把前一个包的数据与设置交给另一个插件。不是同一个插件就换一个 id：`remove-entry` 之后带 `id` 调 `add-entry`。
</Note>

转归属没有单元测试：它只是依次调两个插件的服务，要在隔离 home 里装上数据插件、设置插件后调 `transfer-owner` 验证。
