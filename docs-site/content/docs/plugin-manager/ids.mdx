# id 与归属

**本页回答**：条目 id 是什么、为什么不能改；装包时 id 怎么选、为什么要看磁盘上的归属记录；手动给的 id 什么时候被拒；插件改了包名怎么接着用旧数据。

## id 是身份，一经确定不改

每条条目有一个 id，写在 `cordis.yml` 里；数据插件、设置插件都按 id 给这条条目分目录、分区。改了 id，原来的设置与数据就留在旧分区里，再也读不到，所以插件管理没有改 id 的命令。界面上给人看的名字是插件自报的名字，插件管理不存显示名。

- 字符集是 kebab-case：小写字母、数字、单个连字符分段。数据插件与设置插件用同一套字符集校验，三处必须一起改——生成的 id 通不过它们的校验，这条条目就存不下任何设置和数据
- 默认 id 是包名去掉 scope 与最外层 `gwb-` 前缀：`@godcreator/gwb-py-cli` → `py-cli`；一个字符都剩不下时用 `plugin`
- 重名时加数字后缀：`py-cli-2`、`py-cli-3`，中间空着的号先补上

## 选 id 时看磁盘上的归属记录

数据插件、设置插件都记着每个 id 属于哪个包，删了条目也还在。插件管理选 id（`install`、不给 id 的 `add-entry`）时把这两份记录和条目树一起看。默认 id 去掉了 scope，`@a/gwb-foo` 和 `@b/foo` 都叫 `foo`；删掉条目后它的数据与设置还留在磁盘上。只按条目树判断重名，空出来的 `foo` 会被下一个同名的包拿走，读到前一个包的数据。

- **先沿用**：磁盘上只属于本包、条目树上又空着的 id，说明这个包装过又卸了，沿用它，数据与设置原样接上；有好几个时默认 id 优先，其余按字典序
- **否则从默认 id 起加后缀**：条目树上已有的、磁盘上有一份属于别的包的，都跳过
- **手动给的 id**（`add-entry` 带 `id`）：条目树上已被占用、或磁盘上属于别的包，直接拒绝，错误里写明属于谁、指向 `transfer-owner`

## 转归属：transfer-owner

同一个插件改了包名、要继续用旧数据时，用 `transfer-owner {"id","pkg"}` 把这个 id 的数据目录与设置分区一起转给新包名，再 `remount` 那条条目。`id` 写完整 entryId 或只写 id 都认，条目树上不必有这条。归属记录拦住的是「别的包读到这份数据」；包改名以后，新包名在记录里也是「别的包」，要人确认是同一个插件才能放行。

数据目录、设置分区归数据插件、设置插件管，插件管理不自己拼路径去碰它们，只调这两个插件服务上的 `owners` / `transferOwner`。转归属要两份一起改，哪个插件没装就直接报错、哪一份都不转，不留下「数据转了、设置没转」的半截状态。

<Note>
**不是同一个插件，别转归属**：那等于把前一个包的数据与设置交给另一个插件。不是同一个插件就换一个 id：`remove-entry` 之后带新的 `id` 调 `add-entry`。
</Note>

两个真插件的服务要在隔离 home 里装上它们后调 `transfer-owner` 验证。
