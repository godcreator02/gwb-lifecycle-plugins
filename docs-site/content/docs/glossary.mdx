# 术语表

**本页回答**：这个仓里反复出现的词各指什么，一个词一行，正本（定义它的那一页或那处代码）指过去。

收三类：这个生态自己造的词、通用词在这里有特定含义的、读者第一次见会问「这是什么」的。通用编程词不收。

| 术语 | 一句话 | 正本在哪 |
| --- | --- | --- |
| 件 | 工作台里一个可装可卸的能力单位。装进去才有它的命令，挂不上就什么都没有 | 内核仓的站 |
| home | 一套独立的世界：装了哪些件、数据、设置、日志，各自分家。同一台机器上可以有很多个 | 内核仓的站 |
| 条目 | 一份声明，说这个 home 要挂这个包。装了包不等于有条目，有条目不等于挂上了 | 件仓的站 |
| entryId | 一条条目的身份。停用、启用、改名都按它指人 | 件仓的站 |
| 日常 home | 人每天在用的那一个。开发版永远不进它 | 现状区 `dev` 页 |
| 隔离 home | 为一次验证新开、验完就清的 home。一次验证开一个新的，不复用上一次留下的 | 现状区 `home` 页 |
| 控制台 home | 改一版看一版那条链自己住的那个 home。它操作别的 home，不操作自己 | 现状区 `dev` 页 |
| 本机源 | 这台机器上那个只服务自家包的 npm 源。发版与装机都走它，不碰公网 | 现状区 `registry` 页 |
| 开发版 | 一次性的版本号，只为把这一刻的改动送进一个隔离 home。它不顶掉正式版 | 现状区 `dev` 页 |
| 重挂 | 把一条条目停用再启用，让它重新求值。换了版本号才真的换得动代码 | 现状区 `dev` 页 |
| 取证 | 换完之后回头找「它真的在干活」的证据。挂上了不算，日志里没有新错才算 | 现状区 `dev` 页 |
| 调试口 | 内核起的时候在命令行上开的那个浏览器调试端口。从外面够到一张正在跑的页全靠它 | 现状区 `cdp` 页 |
| 命令总线 | 件把能力挂上去的那张表。界面、命令行、agent 调的是同一张 | 件仓的站 |
| 说明书 | 随包发、由件挂给 agent 的那份正文。知识跟着它描述的代码走 | 生成正本区 |
| 建仓 | 把一个新件的骨架落进一个新文件夹，件那半与站那半各自落地 | 现状区 `scaffold` 页 |
| 纯机 | 不碰盘、不起进程、只喂输入看输出的那一半逻辑。它的对面是只会动手不做判断的那一层 | 现状区 `system-map` 页 |

一个词进表的门槛：在两页以上出现，或者读者第一次见会问「这是什么」。名字定了就别改口，改口是历史，去轨迹区记一张卡。
