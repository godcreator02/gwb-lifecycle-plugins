# 术语表

**本页回答**：这个仓里反复出现的词各指什么，一个词一行，正本（定义它的那一页或那处代码）指过去。

收三类：这个生态自己造的词、通用词在这里有特定含义的、读者第一次见会问「这是什么」的。通用编程词不收。

| 术语 | 一句话 | 正本在哪 |
| --- | --- | --- |
| 插件 | 工作台里一个可装可卸的能力单位。装进去才有它的命令，挂不上就什么都没有 | 内核仓的站 |
| home | 一套独立的世界：装了哪些插件、数据、设置、日志，各自分家。同一台机器上可以有很多个 | 内核仓的站 |
| 条目 | 一份声明，说这个 home 要挂这个包。装了包不等于有条目，有条目不等于挂上了 | 插件仓的站 |
| entryId | 一条条目的身份。停用、启用、改名都按它指人 | 插件仓的站 |
| 日常 home | 人每天在用的那一个。开发版永远不进它 | 现状区 `dev` 页 |
| 隔离 home | 为一次验证新开、验完就清的 home。一次验证开一个新的，不复用上一次留下的 | 现状区 `home` 页 |
| 控制台 home | 改一版看一版那条链自己住的那个 home。它操作别的 home，不操作自己 | 现状区 `dev` 页 |
| 团队源 | NAS 上常驻的 Verdaccio（反代 `https://git.tianshen02.online:28377/api/packages/team/npm/`）。gwb 线的发版与装机都走它；公共包由它代理 npmjs。运维正本在 NAS 仓的 verdaccio 篇 | — |
| 开发版 | 一次性的版本号，只为把这一刻的改动送进一个隔离 home。它不顶掉正式版 | 现状区 `dev` 页 |
| 重挂 | 把一条条目停用再启用，让它重新求值。换了版本号才真的换得动代码 | 现状区 `dev` 页 |
| 取证 | 换完之后回头找「它真的在干活」的证据。挂上了不算，日志里没有新错才算 | 现状区 `dev` 页 |
| 调试端口 | 内核起的时候在命令行上开的那个浏览器调试入口。从外面够到一张正在跑的页全靠它，但**它不是地址**：地址是 home 名，端口是查出来的 | 现状区 `cdp` 页 |
| 运行时记录 | 一个 home 此刻的身份落在盘上那一份：谁在跑、开在哪两个端口。写它的是内核与 mcp 插件，别人只读 | 现状区 `home` 页 |
| 按名字定位 | 说出 home 名，让工具自己去记录里查端口。**够一个 home 只有这一条路**，几处入口都不收端口 | 现状区 `home` 页 |
| 验活 | 读一份运行时记录之后，回头确认它说的那个进程还在、那个端口还归它。记录只说「曾经」，验活才说「此刻」 | 现状区 `home` 页 |
| 交叉核对 | 连上那张页之后，拿它自报的 home 名跟你要的那个对一次。记录回答「你要的是哪个」，页面回答「你连上的实际是哪个」 | 现状区 `cdp` 页 |
| 命令总线 | 插件把能力挂上去的那张表。界面、命令行、agent 调的是同一张 | 插件仓的站 |
| 说明书 | 随包发、由插件挂给 agent 的那份正文。知识跟着它描述的代码走 | 生成正本区 |
| 建仓 | 把一个新插件的骨架落进一个新文件夹，插件那半与站那半各自落地 | 现状区 `scaffold` 页 |
| 纯机 | 不碰盘、不起进程、只喂输入看输出的那一半逻辑。它的对面是只会动手不做判断的那一层 | 现状区 `system-map` 页 |

一个词进表的门槛：在两页以上出现，或者读者第一次见会问「这是什么」。名字定了就别改口，改口是历史，去轨迹区记一张卡。

## 退役的词

2026-09-13 起现状面与生成正本不再用这些词（改口判据见[轨迹区](/trajectory/2026-09-13-terminology-rename)）。旧卡与更早的会话记录里还见得到，意思如下：

| 词 | 指的是 |
| --- | --- |
| **件 / 枚件** | 插件。件仓＝插件仓，站件＝站点插件，写件＝写插件 |
| **口** | 多数是端口（调试口、CDP 口、MCP 口、随机口、挑口），少数是入口（装机口、能被 agent 调到的口） |
| **门** | 入口（「cdp 是门」＝「cdp 是入口」；「开门」＝开调试端口） |
| **格** | 窗格（如旧卡里的「状态格」）。指记录里一个字段的那种「格」（「记录里那格」）是正常用法，没退 |
