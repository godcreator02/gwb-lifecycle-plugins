# 插件之间怎么连

**本页回答**：本仓插件提供哪些服务、命令与事件；注入了哪些服务、是必需还是局部注入、peer 怎么写；按名字调用了别的插件的哪些命令、用了哪些约定通道。

每张表下面是钉码，按内容钉在服务名、`inject` 写法、peer 条目、命令名、文件名这些字面量上：源码里的字面量改了，这一页就报出来。这一页的格式见规矩页[插件之间怎么连写成一页](/docs/rules/wiring)，是约定，没有工具查。

peer 的写法照[用到的插件写 peer](/docs/rules/plugin-peers)：跨仓的插件写 `^<源上 latest>`，同仓的插件写 `workspace:^`、发版时换成 `^<版本号>`；只在 `ctx.inject([...], fn)` 里用、缺了只少一部分功能的标 `optional: true`。两个包都不按值 import `cordis`，peer 里没有它。

### 注入

| 服务 | 提供方包 | 必需 / 局部注入 | peer 写法 | 用来做什么 | 缺了会怎样 |
| --- | --- | --- | --- | --- | --- |
| `gwbCommands` | `@godcreator/gwb-commands` | 必需（`export const inject`） | `^0.5.0` | 登记除 `devkit.cdp` 外的 8 条命令；就绪日志用 `list()` 列出此刻总线上本包的命令 | 插件不加载：cordis 等到这个服务出现才调用 `apply`；`apply` 里取不到它就抛错 |
| `gwbShell` | `@godcreator/gwb-shell` | 局部注入 | `^0.14.0`，`optional: true` | `describeSelf` 报显示名 | 插件清单里没有显示名，别的不受影响 |
| `gwbNodeCli` | `@godcreator/gwb-node-cli` | 局部注入 | `^0.4.7`，`optional: true` | 把 `bin/cdp.mjs` 登记成 `devkit.cdp` | 没有 `devkit.cdp` 命令；`devkit.dev` 不受影响，它自己启动 `bin/cdp.mjs` 子进程 |
| `gwbSkills` | `@godcreator/gwb-skills` | 局部注入 | `^0.4.5`，`optional: true` | 登记 `skills/` 下两份说明书 | agent 读不到这两份说明书，命令照常 |
| `gwbKernel` | 内核包 `@godcreator/gwb-kernel-desktop` | 不写进 `inject`，用 `requireKernel` 取 | `^0.7.0` | `version`：`devkit.home.new` 装进新 home 的内核包版本、建仓时模板 peer 里内核包的下限；`dataDir`：本插件自己所在的 home，`devkit.dev` 拒绝以它为目标，建仓从它的 `node_modules` 读命令总线与外壳的版本 | 用到它的命令抛错「ctx.gwbKernel 不在」 |

**外壳在 peer 里是可选的，但建仓要读它装着的版本**：`devkit.scaffold` 与 `devkit.scaffold.plugin` 直接读本 home 的 `node_modules/@godcreator/gwb-shell/package.json`（命令总线同理）取版本号写进模板 peer，不经 `gwbShell` 服务；home 里没装外壳时这两条命令报错、什么都不写，两条命令的 `usage` 里写着这个前提。

### 按名字调用与约定通道

| 通道 | 对方 | 名字 | 用来做什么 |
| --- | --- | --- | --- |
| 按值 import 主入口（[插件之间怎么交互](/docs/rules/interaction)明文允许的例外） | `@godcreator/gwb-plugin-manager` | `locatePnpm`、`homePnpmEnv`、`KERNEL_PACKAGE`、`isCaretRange`、`tailLines`、`LIST_COMMAND`、`INSTALL_COMMAND`、`UPDATE_COMMAND` | 找 pnpm、在 home 里启动 pnpm 的环境、内核包名与 peer 范围的判定、取输出最后几行、`devkit.dev` 调的三条命令名；规则只有插件管理那一份。缺了模块 import 不到，插件加载失败。见接缝页 [devkit 调插件管理](/docs/seams/plugin-manager-calls) |
| 经 CDP 在目标 home 的页面里调命令 | 目标 home 的插件管理 | `plugin-manager.update`（带 `specs`）、`plugin-manager.install`、`plugin-manager.list` | `devkit.dev` 装包、新建条目、重新加载、等插件管理自己的条目回来、取证；没成回 `ok: false`，带插件管理回执里的原因 |
| 经 CDP 在目标 home 的页面里调命令 | 目标 home 的外壳 | `shell.env` | 装了内核包、重启目标 home 之后轮询 `versions.kernel`，直到是这次打包的版本号 |
| 读文件 | 各 home 的 `runtime.json`（内核与 MCP 入口插件写） | `<home>/runtime.json` | 按名字查 pid 与调试端口；只读不写 |
| 读文件 | 目标 home 的日志 | `<home>/gwb.log` | `devkit.dev` 取证：新增部分里没有 error |
| 读文件 | 目标 home 的清单 | `<home>/package.json` | `devkit.dev` 分出已装（走 `update`）与没装（走 `install`）的包；只读 |
| 写文件 | 目标 home 的 `dev-packs/` | `<home>/dev-packs/<包文件>` | 开发版的包文件；每版一个新路径，旧的不删 |
| 写文件与安装 | 新 home | `<home>/cordis.yml`、`pnpm add`（内核包、`cordis`、七个基础插件） | `devkit.home.new` 在新 home 启动之前写好基础插件的条目、装包（那时插件管理还没运行） |
| 读文件 | 本 home 装着的命令总线与外壳 | `<本 home>/node_modules/@godcreator/gwb-commands/package.json`、`.../gwb-shell/package.json` | 建仓与加插件时模板 peer 的版本号；没装就报错 |
| 环境变量与命令行参数 | 宿主安装版应用 | `GWB_HOME=<home 名>`、`--remote-debugging-port=<端口>` | `devkit.home.new` / `open` 再启动一次宿主，指定 home 与调试端口 |
| 读被发版的包 | 包目录 `node_modules` 里装好的内核包与外壳 | 内核包的 `dist/index.html`（页面 importmap）、外壳的 `theme.reference.css`（主题令牌） | 发版前检查的浏览器侧 import 名单与样式检查的色名 |
| 子进程 | pnpm、git、`tasklist` / `netstat` / `taskkill` | | 构建、打包、发布、`pnpm view` 查源；查工作区干不干净；查进程与端口、终止进程树 |

### 按名字调用与约定通道

插件管理不按名字调用别的插件的命令，也不推事件；它直接碰的是 loader、cordis 的内部状态与 home 里的文件。

| 通道 | 对方 | 名字 | 用来做什么 |
| --- | --- | --- | --- |
| loader 的条目树 | `@cordisjs/plugin-loader`（内核加载） | `ctx.fiber.entry.parent.tree` 的 `store`、`create`、`update`、`remove` | 读条目、加删条目、启用停用、重新加载，改动由 loader 写回 `cordis.yml`；取不到条目树就在构造时报错。见接缝页[条目树 loader](/docs/seams/entry-tree) |
| 抄了一份 cordis 的状态数字 | cordis 的 `FiberState`（`const enum`，引用不到） | `PENDING`、`LOADING`、`ACTIVE`、`FAILED`、`DISPOSED`、`UNLOADING` 的数字顺序 | `list` 的 `active` 与重新加载时判断条目到哪一步；`tests/fiber-state.test.ts` 对照 cordis 的定义 |
| 子进程 | 用户装的 pnpm 12 | `pnpm add` / `remove` / `outdated --json`，环境带 `pnpm_config_auto_install_peers=false` | 装卸与升级 home 里的包；不自动补装缺的 peer |
| 读文件 | home 的清单与装着的包 | `<home>/package.json`、`<home>/node_modules/<包>/package.json` 与它指向的真实目录 | 装了哪些包、版本、peer 报告；`update` 前后比真实目录找出跟着重新加载的包 |
| 读文件 | 机器级与 home 级 npmrc | `~/.npmrc`、`<home>/.npmrc` | `search` 按 scope 找源地址与 token，只读不写 |
| 网络 | 各条 npm 源 | `GET <源>/-/v1/search` | `search` 检索可装的插件 |
