**本页回答**：devkit 怎么启动一个 home、怎么找到一个正在运行的 home；它依赖内核的哪几样东西；这些东西在 devkit 里写了几份。

## 连接的模块

- devkit 的 `devkit.home.new` / `open` / `rm` / `list` 与 `devkit.dev` 的定位（`src/home.ts`、`src/index.ts`）
- `bin/cdp.mjs`：按 home 名找调试端口
- 内核 exe（内核仓）：读 `GWB_HOME` 决定用哪个 home，启动时写 `<home>/runtime.json`，往 `<home>/gwb.log` 写日志

## 约定

内核需要保证的：`GWB_HOME` 是名字时 home 在 `%APPDATA%\gwb-kernel\homes\<名>`；`runtime.json` 的字段名与含义（字段表见内核仓文档站的「runtime.json」接缝页）；`gwb.log` 一行的格式；认 `--remote-debugging-port`。

devkit 保证：
- `runtime.json` 只读不写；进程退出后记录留着
- 定位一个 home 只凭名字，端口从记录里查，连上后再用页面自报的名字核对
- `default` 不删（不带 `force`），正在运行的 `default` 带 `force` 也不删

**这些都靠约定**：devkit 与内核之间没有代码接口。`runtime.json` 的字段名写在内核的 `main.ts`、devkit 的 `parseRecord` 与 `cdp.mjs` 的 `portOf` 三处；home 根目录写在内核的 `main.ts` 与 `cdp.mjs` 的 `homesRootOf` 两处（devkit 的 `src/index.ts` import 后者）；日志行格式写在内核的 `main.ts` 与 `dev.ts` 的 `errorLines` 两处。

有一处与内核现状对不上：内核仓 `main.ts` 里没有检查 `GWB_HOME` 的正则：值里带路径分隔符就当目录用，否则拼到 `homes` 下。「就是内核的校验正则」只是 devkit 注释里的说法。

devkit 所在的 home 用带路径的 `GWB_HOME` 启动时，它自己不在 home 根下，但 home 根照样按 `%APPDATA%` 算，`devkit.home.*` 与 `devkit.dev` 找的仍是 `%APPDATA%\gwb-kernel\homes` 下的 home。

## 不负责的事

- devkit 不构建内核、不认内核仓，启动的永远是宿主正在运行的那个 exe
- devkit 不写 `runtime.json`，也不删它
- 内核不知道 devkit：它写 `runtime.json`、日志，给谁读都一样
