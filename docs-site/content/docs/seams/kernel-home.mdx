**本页回答**：devkit 怎么启动一个 home、怎么找到一个正在运行的 home；它依赖内核的哪几样东西、这些东西在 devkit 里写了几份；内核与 devkit 各保证什么。

## 连接的模块

- devkit 的 `devkit.home.new` / `open` / `rm` / `list` 与 `devkit.dev` 的定位（`src/home.ts`、`src/index.ts`）
- `bin/cdp.mjs`：按 home 名找调试端口
- 内核 exe（内核仓 `apps/desktop/src/`）：读 `GWB_HOME` 决定用哪个 home，启动时写 `<home>/runtime.json`，往 `<home>/gwb.log` 写日志

**gwb.log**：`devkit.dev` 在装包之前记下日志文件的长度，最后只读新增的部分；装了内核包时改在旧内核退出之后、新内核启动之前记，只读新内核写的。内核 0.10.0 起这个文件一行一个 JSON，五个键 `ts`、`level`、`source`、`name`、`msg`，正文里的换行在 JSON 字符串里转义，所以一条记录就是一行。`level` 是 `error` 的算失败、`warn` 的另报，回执里每条写成 `<ts> <level> <name> <正文第一行>`。有一行不是 JSON、缺字段、或 `level` 不是 `error` / `warn` / `info` / `debug`，整段不判，`devkit.dev` 回失败并说目标 home 的内核要 0.10.0 起；更早的内核写的文本行不兼容。格式由内核定（内核仓文档站的日志规格）：

内核对 `GWB_HOME` 不做形状检查：值里带路径分隔符就当目录用，否则拼到 `homes` 下。devkit 这条正则比内核严，它旁边的注释说「就是内核的校验正则」，与内核现状不符。

## 约定

内核需要保证的：`GWB_HOME` 是名字时 home 在 `%APPDATA%\gwb-kernel\homes\<名>`；`runtime.json` 的字段名与含义（字段表见内核仓文档站的「runtime.json」接缝页）；`gwb.log` 一行一个 JSON、五个键的名字与含义；认 `--remote-debugging-port`。

devkit 保证：

- `runtime.json` 只读不写；进程退出后记录留着
- 定位一个 home 只凭名字，端口从记录里查，连上后再用页面自报的名字核对
- `default` 不带 `force` 不删，正在运行的 `default` 带 `force` 也不删

**这些都靠约定**：devkit 与内核之间没有代码接口。`runtime.json` 的字段名写在内核、devkit 的 `parseRecord` 与 `cdp.mjs` 的 `portOf` 三处；home 根目录写在内核与 `cdp.mjs` 的 `homesRootOf` 两处；日志一行的键名写在内核与 `dev.ts` 的 `LOG_RECORD_KEYS` 两处。内核改了其中任何一样，devkit 这边没有类型或测试会报错。

devkit 所在的 home 用带路径的 `GWB_HOME` 启动时，它自己不在 home 根下，但 home 根照样按 `%APPDATA%` 算，`devkit.home.*` 与 `devkit.dev` 找的仍是 `%APPDATA%\gwb-kernel\homes` 下的 home。

## 不负责的事

- devkit 不构建内核、不认内核仓，启动的永远是宿主正在运行的那个 exe
- devkit 不写 `runtime.json`，也不删它
- 内核不知道 devkit：它写 `runtime.json`、日志，给谁读都一样
