**本页回答**：`gwb.testedKernel` 与 `gwb.requires` 写在哪、谁读、拿什么比；判法为什么有两份、两份靠什么保持一样。

## 连接的模块

- 插件包的 `package.json`：`gwb.testedKernel` 写这个插件验过的内核版本号；`gwb.requires` 写它要求 home 里别的包最低到哪个版本
- devkit 的 `devkit.release`（`src/release.ts` + `src/tested-kernel.ts`）：发版前检查
- 插件管理的 `plugin-manager.list`（`src/index.ts` + `src/tested-kernel.ts` + `src/requires.ts`）：按包报 `testedKernel` 与 `kernelUntested`、`requires` 与 `unmetRequires`
- 内核：内核服务 `gwbKernel` 的 `version`，由内核仓提供
- home 里装的别的插件：被 `gwb.requires` 点名的包，插件管理读它在 `node_modules` 里的 `package.json` 取 `version`

<Diagram name="seam-version-fields" title="两个字段，两处读：devkit.release 在发版时拒，plugin-manager.list 在 home 里只报告">
- 插件包的 `package.json` 里写 `gwb.testedKernel` 与 `gwb.requires`
- `devkit.release` 发版时只查插件包：`gwb.testedKernel` 拿 devkit 所在 home 的 `gwbKernel.version` 比版本线；`gwb.requires` 查写法（是对象、值是 x.y.z、包在 dev 里、不高于 dev 下限）；没过就一个都不发，回执写改成什么
- `plugin-manager.list` 每次列出时对每个包：`gwb.testedKernel` 拿插件管理所在 home 的 `gwbKernel.version` 比；`gwb.requires` 拿 home 里 `node_modules/<包>/package.json` 的版本比；报 `kernelUntested` 与 `unmetRequires`，只报告、照常加载
- 判法两个包各有一份（两个 `tested-kernel.ts`、两个 `isMinimumVersion`），不跨包 import，对照测试拿同一组输入比两份的结果
- 内核不读这两个字段；两处比的可以是不同的 home
</Diagram>

## 约定

devkit 保证：插件包的 `gwb.testedKernel` 没写、不合法、不在当前内核版本线上，一个包都不发，回执里写改成什么；写了 `gwb.requires` 而写法不对，同样一个包都不发。不是插件的包不查。

插件管理保证：`kernelUntested` 与 `unmetRequires` 只报告，不拦加载、不拦安装。

**两份判法保持一样靠同一个提交一起改，加对照测试把关**：比对规则的「改规则时两份一起改」写在两份 `tested-kernel.ts` 的文件头、本仓 AGENTS 的「本仓还有插件管理」与本站[在哪个内核上测过](/docs/plugin-manager/kernel-compat)，最低版本号判法的写在两处 `isMinimumVersion` 的注释；devkit 的 `tests/tested-kernel-parity.test.ts` 把两份比对规则都 import 进来，拿同一组版本号与包清单跑三个函数，`tests/requires-parity.test.ts` 拿同一组字符串跑两份 `isMinimumVersion`，返回值或抛出的错误不同就失败。

插件管理的 `loader.test.ts` 还把 loader、include、cordis 三个 `devDependencies` 的版本与 `gwb.testedKernel` 那个内核对齐，见[条目树 loader](/docs/seams/entry-tree)。

建仓模板的 `template/pkg/package.json.tpl` 写 `gwb.testedKernel`，值是占位符 `{{testedKernel}}`：`devkit.scaffold` 与 `devkit.scaffold.plugin` 填入运行命令的那个 home 的 `gwbKernel.version`，所以新仓在同一个内核上 `devkit.release` 时过得了这一项检查；结构体检不查这个字段。模板不写 `gwb.requires`：新插件还没用到别的插件的新东西。

## 不负责的事

- 内核不读 `gwb.testedKernel` 与 `gwb.requires`，版本对不上、要求没满足的插件照常加载
- devkit 只在发版时查，装进 home 时不查；插件管理只报，不拒，也不替插件升级被要求的包
- 两处比的都是调用方所在 home：`devkit.release` 比 devkit 所在 home 的内核，`list` 比插件管理所在 home 的内核与装的包，二者可以是不同的 home
- devkit 不查 `gwb.requires` 要求的版本在源上发没发过：要求不高于 dev 下限，而 dev 下限由依赖范围那项检查对照源上的 latest
