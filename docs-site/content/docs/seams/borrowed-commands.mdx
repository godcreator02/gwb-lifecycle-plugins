**本页回答**：devkit 与插件管理调了哪几条别人的命令、传什么、读回执里的哪个字段；命令不在时各自怎么办；这些约定写在哪。

## 连接的模块

- devkit 的 `devkit.scaffold`、`devkit.audit-structure`、`devkit.audit-deps`（`src/index.ts`、`src/node-audit-deps.ts`、`src/audit.ts`）
- 插件管理的 `plugin-manager.update-all`（`src/index.ts`）
- 被调的插件，都不在本仓：站点插件 `@godcreator/gwb-docs-site`（`docs-site.create`）、docfirst 插件 `@godcreator/gwb-docfirst-workflow`（`docfirst.attach`）、单元文件夹插件 `@godcreator/gwb-unit-folder`（`unit-folder.list`）、外壳 `@godcreator/gwb-shell`（`shell.reload`）

## 约定

devkit 保证：
- 建站那两步失败或命令不在，插件那部分照样留在磁盘上，建仓不算失败；回执的 `docs.built`、`docs.attached` 两个字段说到了哪一步，`note` 与 `nextSteps` 给出补建的两条命令
- `docs-site.create` 在而 `docfirst.attach` 不在时，提醒「立刻补」：`docfirst.attach` 只在还没写过内容的骨架上装得上
- `unit-folder.list` 不在、失败、或回执里没有 `container` 时，要求调用方给 `root`，报错说明，不猜容器根

插件管理保证：`shell.reload` 不在或失败时，回执与日志说「界面要手动刷新」，升级照样算完成。

被调的插件需要保证的——命令名、参数形状、`data.port` 与 `data.container` 这两个字段、`unit.json` 的 `status` / `kind` 取值——**都靠约定**。写在这几处：两个插件源码里的命令名常量与 `usage` 文字、`scaffold.ts` 的 `docsBlock` 与 `nextSteps`、本仓 AGENTS 的「建站是两步」、被调插件各自的说明书（`docs-site`、`unit-folder`）。被调插件改了名字或形状，devkit 这边没有任何类型或测试会报错，表现是「当作没装」而跳过，或读到空的 `port` / `container`。

## 不负责的事

- devkit 不知道站点骨架里有什么、六区怎么装；插件管理不知道外壳怎么重新加载
- devkit 不检查被调命令的版本
- `unit.json` 其余字段 devkit 不读；单元目录的规矩归单元文件夹插件
