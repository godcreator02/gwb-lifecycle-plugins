**本页回答**：`devkit.services` 的数据从哪来；它在 `.d.ts` 里认哪种写法；怎么判断谁是提供方；多个提供方、没有提供方时回什么；插件要让别人知道自己的服务该怎么写。

## 连接的模块

- devkit 的 `devkit.services`：从 `.d.ts` 原文里认服务的纯逻辑在 `src/services.ts`，读 home 磁盘在 `src/node-services-deps.ts`，登记在 `src/index.ts`
- 调用它的那个 home（`gwbKernel.dataDir`）顶层 `node_modules` 里的每个包：它的 `package.json`（取 `name` 与 `version`）与包目录下全部 `.d.ts`（不进包自己的 `node_modules`）

<Diagram name="seam-service-table" title="devkit.services 只有一路数据：home 里各包的 .d.ts">
- 上面是 home 顶层 `node_modules` 里每个包的全部 `.d.ts`，命令在里面找 `declare module 'cordis' { interface Context { 服务名: 类型 } }`，取服务名、类型名、是不是可选（`名?:`）
- 中间是 `devkit.services`，无参数
- 下面两栏：类型定义（interface、class 或 type 别名）就在这个包自己的 `.d.ts` 里的，这个包记进 `providers`；类型是从别的包 import 来的，记进 `declaredAlsoBy`
- `definition` 是第一个提供方里那个类型的定义原文连同紧挨着的文档注释；`providers` 多于一个说明有包带着重复或过期的声明，命令照实列出，不过滤
</Diagram>

## 接口

**读哪些文件**：home 顶层 `node_modules` 里的包目录（`name` 与 `@scope/name` 两层，跳过 `.pnpm`、`.bin` 这类点开头的），每个包读清单的 `name` 与 `version`、包目录下全部 `.d.ts`。清单读不出、缺 `name` 或 `version` 直接报错：

{/* ref file="../plugins/devkit/src/node-services-deps.ts" lines="7-58" */}

**认哪种写法**：`declare module 'cordis'` 块里 `interface Context` 块里的每一项 `名字: 类型;` 或 `名字?: 类型;`。别的模块里的 `interface Context` 不算：

{/* ref file="../plugins/devkit/src/services.ts" lines="55-66" */}

**谁是提供方**：在同一个包的 `.d.ts` 里找这个类型名的定义（`interface`、`class`、`type` 别名，连同紧挨在前面的文档注释），找到就是提供方；`import type { X } from '…'` 只是引用，找不到定义的包记进 `declaredAlsoBy`：

{/* ref file="../plugins/devkit/src/services.ts" lines="72-93" */}

{/* ref file="../plugins/devkit/src/services.ts" lines="103-129" */}

**回执**：`{ home, services: [{ service, providers, type, optional, definition?, declaredAlsoBy }] }`，按服务名排序；`providers` 与 `declaredAlsoBy` 的每一项写成 `<包名>@<版本>`：

## 约定

devkit 保证：只读不写；读的是这个 home 的磁盘，装着的包都算，不管它的条目启没启用；`providers` 有几个列几个，不替调用方挑。

提供服务的插件需要保证的：在自己发布的 `.d.ts` 里给 cordis 的 `Context` 补上这一项，服务的类型也定义在自己的声明里，在类型上写文档注释说明怎么用——`devkit.services` 回执里的 `definition` 就是这段原文。只 `import type` 别人的服务类型、在自己的声明里再补一次同名项的包是使用方。这几条**靠约定**：没有检查查一个包提供了服务却没写声明。

包里带着过期的构建产物时（构建前没清 `dist/`，旧的 `.d.ts` 还在），同一个服务会多出一个提供方；命令不判断哪个是真的，由读回执的人看版本与路径。

## 不负责的事

- 不看 cordis 的运行时状态：服务此刻有没有被提供、由哪个条目提供，看 `plugin-manager.list` 的条目状态
- 不聚合服务上有哪些方法，只给类型定义的原文，方法签名与注释都在里面
- 不列命令：命令按插件查用 MCP 入口的 `search`
