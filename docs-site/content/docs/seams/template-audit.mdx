**本页回答**：结构体检的规则以什么为准；模板改了、规则改了，谁先发现；哪一条判据写了两份。

## 连接的模块

- 建仓模板（`plugins/devkit/template/`）：`repo/` 生成仓根，`pkg/` 生成 `plugins/<短名>/`；由 `src/scaffold.ts` 渲染，`devkit.scaffold` 与 `devkit.scaffold.plugin` 共用 `pkg/`
- 结构体检（`src/structure.ts`）：`devkit.audit-structure` 的规则，只读

## 接口

两边之间没有函数调用，接口就是**模板生成的那棵目录树**：结构体检认的每一条（仓根 `private`、根 `build` 脚本含 `pnpm -r`、`pnpm-workspace.yaml` 有 `plugins/` 那一行、包名 `@godcreator/gwb-<短名>`、`export const name = 'gwb-<短名>'`、`files` 白名单、`prepublishOnly`、包内三份配置、浏览器侧的 `build.ts` 与 `src/client/tsconfig.json`），模板都得满足。规则见[结构体检](/docs/devkit/structure)，模板见[建仓](/docs/devkit/scaffold)。

## 约定

模板保证：生成的仓跑结构体检零发现——建一个仓零发现，再往里加一个插件还是零发现。

结构体检保证：新加一条规则时，模板生成的仓仍然零发现；过不了就先改模板或改规则。

两份正则保持一样**靠约定**：`structure.ts` 的注释写着「与 scaffold.plugin 同一条」；没有测试拿同一组 yaml 分别过两份。往返测试只在模板那份 yaml 上同时经过两份。

模板改布局必须同时通过往返测试，这条写在本仓 AGENTS 的「模板」一节。

## 不负责的事

- 结构体检不管依赖版本与 peer（`devkit.audit-deps` 与 `devkit.release`），不管自述三格（[repo-kit](/docs/seams/repo-kit)），不管构建产物，也不查 `gwb.testedKernel`
- 模板不保证生成的仓能直接 `devkit.release`：模板没写 `gwb.testedKernel`（见[测过哪个内核](/docs/seams/tested-kernel)）
- 往返测试不带文档站（`docs: false`），结构体检本来也不进 `docs-site/`
