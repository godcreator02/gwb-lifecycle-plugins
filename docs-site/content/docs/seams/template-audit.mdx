**本页回答**：结构体检的规则以什么为准；模板改了、规则改了，谁先发现；哪一条判据写了两份。

## 连接的模块

- 建仓模板（`plugins/devkit/template/`）：`repo/` 生成仓根，`pkg/` 生成 `plugins/<短名>/`，`site/plugin.mdx.tpl` 生成文档站现状区的插件页；由 `src/scaffold.ts` 渲染，`devkit.scaffold` 与 `devkit.scaffold.plugin` 共用 `pkg/` 与插件页
- 结构体检（`src/structure.ts`）：`devkit.audit-structure` 的规则，只读

## 接口

两边之间没有函数调用，接口就是**模板生成的那棵目录树**：结构体检认的每一条（仓根 `private`、根 `build` 脚本含 `pnpm -r`、`pnpm-workspace.yaml` 有 `plugins/` 那一行、包名 `@godcreator/gwb-<短名>`、`export const name = 'gwb-<短名>'`、`files` 白名单、`prepublishOnly`、包内三份配置、浏览器侧的 `build.ts` 与 `src/client/tsconfig.json`、`gwb.provides` 与源码对得上），模板都得满足。规则见[结构体检](/docs/devkit/structure)，模板见[建仓](/docs/devkit/scaffold)。

## 约定

模板保证：生成的仓跑结构体检零发现——建一个仓零发现，再往里加一个插件还是零发现。

结构体检保证：新加一条规则时，模板生成的仓仍然零发现；过不了就先改模板或改规则。

两份正则保持一样**靠约定**：`structure.ts` 的注释写着「与 scaffold.plugin 同一条」；没有测试拿同一组 yaml 分别过两份。往返测试只在模板那份 yaml 上同时经过两份。

模板改布局必须同时通过往返测试，这条写在本仓 AGENTS 的「模板」一节。

## 不负责的事

- 结构体检不管依赖版本与 peer（`devkit.audit-deps` 与 `devkit.release`），不管构建产物，也不查 peer 里内核包的范围
- 模板不保证生成的仓能直接 `devkit.release`：依赖版本过不过得了发版前检查，要看发版那时源上的 latest；peer 里内核包的范围，模板写的是建仓时运行命令的内核版本（见[兼容哪个内核](/docs/seams/kernel-peer)）。发版前检查里 `skipLibCheck: false` 的类型检查按模板的 `tsconfig.build.json`（只包含 `src/index.ts`）与 `src/client/tsconfig.json` 查，测试与 `build.ts` 不在其中；模板从内核包 `import type` 的接口类型引用了 `HTMLElement`，内核包的 d.ts 自己声明了 DOM 类型库，插件包 node 侧的 tsconfig 不带 DOM 类型库也能过
- 往返测试不带文档站（`docs: false`），也不写插件页；结构体检本来也不进 `docs-site/`
