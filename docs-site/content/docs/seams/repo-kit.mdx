**本页回答**：repo-kit 给使用方的测试提供了哪几样；使用方怎么接；模板生成的仓用的是哪一版 repo-kit、它的自述检查读哪里的文档。

## 连接的模块

- repo-kit（`packages/repo-kit`，包 `@godcreator/gwb-repo-kit`，不是插件，`keywords` 只有 `gwb`）
- devkit 与插件管理：`devDependencies` 写 `workspace:*`，各自的 `tests/self-report.test.ts` 登记自述守卫
- 模板生成的仓：`template/pkg/` 里的 `tests/self-report.test.ts` 与 `tests/plugin.test.ts` 两份测试，`devDependencies` 写 `^` 范围

**`registerSelfReportGuard(vt, { root, docsDir? })`**：`root` 是包根；`docsDir` 是文档站现状区，缺省是 `root` 下的 `docs-site/content/docs`。只对 `keywords` 含 `gwb-plugin` 的包注册用例，一共五项：

1. `description` 里有「服务 / skill / 命令」三格
2. 源码提供的服务名在 `description` 里都点了名
3. `gwb.provides` 的键与源码提供的服务互为充要，每条 `summary` / `usage` 非空
4. `description` 里的 skill 份数等于 `skills/` 下带 `SKILL.md` 的目录数
5. 源码注入的服务名在 `docsDir` 下的 `.mdx` 里都出现过；`docsDir` 下一个 `.mdx` 都读不到时这一项直接通过

{/* ref file="../packages/repo-kit/src/self-report-guard.ts" lines="105-155" */}

## 约定

repo-kit 保证：只导出上面几样；不是插件的包一条用例都不注册；替身上下文只有 `logger`、`effect`、`gwbShell.registerPane`、`gwbCommands.register`。

使用方保证：
- devkit 与插件管理显式传 `docsDir`，指到仓根的文档站（插件管理只指到 `plugin-manager/` 那组页）

{/* ref file="../plugins/devkit/tests/self-report.test.ts" lines="13-17" */}

- 模板里的测试也显式传 `docsDir`：生成的仓里文档站在仓根，插件包在 `plugins/<短名>/`，所以指到仓根的 `docs-site/content/docs`。现状区要写出模板插件注入的 `gwbCommands`、`gwbShell`，第五项才通过：`devkit.scaffold` 在站装好六区之后、`devkit.scaffold.plugin` 在仓里有装好六区的站时，各写一页插件页 `plugins/<短名>.mdx`，写的就是这两个服务名（见[建仓与加插件](/docs/devkit/scaffold)）。没建站时目录不存在，第五项直接通过

{/* ref file="../plugins/devkit/template/pkg/tests/self-report.test.ts.tpl" lines="16-20" */}

## 不负责的事

- repo-kit 不检查命令条数的真伪，只检查「命令 N 条」或「命令无」的写法
- repo-kit 不管结构（`files` 白名单、派生链）与依赖版本，那是[结构体检](/docs/seams/template-audit)与 `devkit.release` 的事
- repo-kit 不知道谁在用它；改断言就是给所有使用方改行为，要发一版、使用方升级
