**本页回答**：devkit 的几条命令对传给它的仓做了哪些假设；每条假设在哪几处代码里用到；不满足时各自怎样。

## 连接的模块

- devkit 的 `devkit.dev`（`src/dev.ts`）、`devkit.release`（`src/release.ts`、`src/artifact-check.ts`）、发布内容的组装（`src/node-dev-deps.ts`）、`devkit.audit-structure`（`src/structure.ts`）、`devkit.audit-deps`（`src/audit.ts`、`src/node-audit-deps.ts`）
- 被处理的插件仓：别人的仓，也包括本仓

## 约定

devkit 保证：
- 除了 `pnpm build` 生成的构建产物，这些命令不改仓里的文件；发布内容在系统临时目录里组装
- 假设不满足时报错并说明缺了什么，不替调用方补（不补构建、不猜包目录、不改 `files`）

被处理的仓需要满足上面这几条，**全部靠约定**：没有一份检查把它们合在一起查。散在这几处：建仓模板生成的仓天然满足；结构体检查其中一部分（仓根 `build` 含 `pnpm -r`、`files` 白名单、`prepublishOnly`、`plugins/` 布局）；其余只写在各命令的 `usage` 与说明书「gwb-devkit」「gwb-release」里。

## 不负责的事

- devkit 不决定一个仓该有几个包、怎么分组，只按上面的目录名去找
- `devkit.dev` 不看 git 状态，未提交的改动照样发成开发版
- 结构体检不看依赖版本、`gwb.testedKernel` 与 git 状态
