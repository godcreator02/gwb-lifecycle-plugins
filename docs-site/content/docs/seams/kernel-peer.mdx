**本页回答**：插件在哪里声明兼容哪个内核、用到哪些别的插件；谁读、拿什么比；内核范围的比对规则放在哪、devkit 怎么用到它；devkit 与插件管理各保证什么。

## 连接的模块

- 插件包的 `package.json`：`peerDependencies` 里写内核包 `@godcreator/gwb-kernel-desktop` 的范围，声明兼容哪些内核；再写用到的别的插件的范围，只在 `ctx.inject([...], fn)` 里用的在 `peerDependenciesMeta` 标 `optional`
- devkit 的 `devkit.release`（`plugins/devkit/src/release.ts`）：发版前检查
- 插件管理的 `plugin-manager.list`（`plugins/plugin-manager/src/index.ts`、`src/kernel-compat.ts`、`src/kernel-upgrade.ts`、`src/peers.ts`）：按包报 `unmetPeers`，内核包与别的插件都在里面；`src/kernel-compat.ts` 里判写法的 `isCaretRange` 经主入口导出给 devkit
- 内核：内核服务 `gwbKernel` 的 `version`；内核包和插件一样装在 home 里
- npm 源：`devkit.release` 问 peer 里每个 gwb 插件的 `dist-tags.latest`，去哪个源问由用户级 `~/.npmrc` 的 scope 路由决定
- home 里装的别的插件：被 peer 点名的包，插件管理读它在 `node_modules` 里的 `package.json` 取 `version`

- 插件包的 `package.json` 的 peer 里写内核包的范围与用到的别的插件的范围

- `plugin-manager.list` 每次列出时对每个包：是插件（keywords 含 `gwb-plugin`，内核包与 `cordis` 除外）才拿 peer 内核包的范围和插件管理所在 home 的 `gwbKernel.version` 比；peer 里别的插件拿 home 里 `node_modules/<包>/package.json` 的版本比；没满足的都列进 `unmetPeers`，只报告、照常加载
- 内核范围的比对规则只有一份，在插件管理的 `kernel-compat.ts`；devkit 从插件管理的主入口 import 其中「只许 `^x.y.z`」那一条（devkit 的 peer 里写着插件管理）
- 内核不读 peer；只有 `list` 拿范围对照内核

## 约定

devkit 保证：插件包 peer 里的内核包没写、不是 `^x.y.z`，一个包都不发，回执里写改成什么；peer 里有插件以外的包、gwb 插件不是 `^x.y.z` 或和源上 latest 不在同一条线，同样一个包都不发。不是插件的包不查。

插件管理保证：`unmetPeers` 只报告，不拦加载、不拦安装，也不替插件装或升级它 peer 里的插件；经主入口导出的比对规则是纯函数，改了它，devkit 的发版前检查跟着变，改名字、签名或行为是破坏性变更（见[什么算破坏性变更](/docs/plugin-manager#什么算破坏性变更)）。

**是不是插件，插件管理与 devkit 用同一条判法**：`keywords` 含 `gwb-plugin`。插件管理用它决定要不要看这个包的内核范围与 peer，devkit 发版前检查用它判 peer 里能不能写这个包、要不要和源上 latest 比同一条线。两处各写一份，规则只有这一句。

建仓模板的 `template/pkg/package.json.tpl` 在 peer 里写内核包，值是 `^{{kernelVersion}}`：`devkit.scaffold` 与 `devkit.scaffold.plugin` 填入运行命令的那个 home 的内核版本号（只取 x.y.z），所以新仓在同一个内核上 `devkit.release` 时过得了这一项检查（见[模板与发版前检查](/docs/seams/template-release)）。模板的 peer 里还写着它用到的命令总线与外壳，值是 `^{{commandsVersion}}`、`^{{shellVersion}}`，由这两条命令读那个 home 里装着的版本填（见[建仓与加插件](/docs/devkit/scaffold#数据结构)），模板里不写死数字。

## 不负责的事

- 内核不读 peer 里的范围，范围不包含、peer 没满足的插件照常加载
- devkit 只在发版时查，装进 home 时不查；插件管理只报，不拒
- 只有 `list` 拿范围对照内核：它比插件管理所在 home 正在运行的内核与装的包；`devkit.release` 不对照任何内核
- devkit 不查 peer 里插件的下限在源上发没发过：插件仓里 `pnpm install` 按 peer 装被依赖的插件，下限写了源上没有的版本就装不上
