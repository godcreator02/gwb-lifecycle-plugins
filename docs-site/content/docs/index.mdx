**本页回答**：devkit 仓是什么；两个包怎样配合，每两个模块之间靠哪条接缝相连、接口是什么、细节在哪一页；每个包讲什么、在哪一页；带着不同的目的来，接着读哪几页。

## 是什么

god 工作台写插件用的一套东西：开发套件 `gwb-devkit`（建仓、测试 home、改一版看一版、发正式版、服务总览、CDP 驱动）、插件管理 `gwb-plugin-manager`（唯一给 home 装包、改条目的插件），两个都是 home 里的普通插件。写插件要守的规矩在[写插件的规矩](/docs/rules)，为什么这么切分见[关键设计](/docs/design)，怎么改、怎么发版见[开发](/docs/develop)。

## 接缝图

<Diagram name="seam-map" title="虚线框是包，连线是接缝，编号对应下面的表">
- 本仓两个包：开发套件（建仓、服务总览、测试 home、改一版看一版、发正式版、CDP 驱动、建仓模板）、插件管理
- 仓外：工作台服务（`gwbCommands`、`gwbNodeCli`、`gwbSkills`）；别的插件的命令（`docs-site.create`、`docfirst.attach`）；内核与 home（exe、`runtime.json`、`gwb.log`）；cordis loader 的条目树；pnpm 与包源（npm 源、两份 npmrc、gitea 插件的设置）；工作台页面（`window.gwb`）；服务的类型声明（home 里各包的 `.d.ts`）；被测插件仓
- 实线接缝有代码接口；点线接缝（3、4、5、6、7、10、11）只靠约定：命令名、文件格式、字段名或「两处一起改」
</Diagram>

## 十一条接缝

| # | 接缝 | 连接的模块 | 接口 | 细节在 |
| --- | --- | --- | --- | --- |
| 1 | 工作台服务 | 开发套件、插件管理 ↔ 命令总线、命令行工具、说明书 | 登记命令、登记 `devkit.cdp`、登记说明书 | [工作台服务](/docs/seams/workbench) |
| 2 | devkit 调插件管理 | 开发套件 ↔ 插件管理 | 从插件管理主入口 import pnpm 定位与版本范围判定；经 CDP 调 `plugin-manager.list` / `remount`（约定）；`home.new` 自己写条目、装内核包与基础插件（约定） | [devkit 调插件管理](/docs/seams/plugin-manager-calls) |
| 3 | peer 里的内核包与插件（约定） | 插件 peer 里的内核包范围、用到的别的插件的范围 ↔ `devkit.release`、`plugin-manager.list` | 内核范围比对规则一份，在插件管理；peer 里的插件发版时比源上 latest、在 home 里比装着的版本 | [peer 里的内核包与插件](/docs/seams/kernel-peer) |
| 4 | 模板与发版前检查（约定） | 建仓模板 ↔ `devkit.release` 的发版前检查 | 模板生成的插件包在同一个内核上过得了 peer 那几项；模板带的产物测试与发版前检查用同一套包名 import 名单 | [模板与发版前检查](/docs/seams/template-release) |
| 5 | 借用别的插件的命令（约定） | 建仓、插件管理 ↔ 站点插件、docfirst、外壳 | 按名字调 `docs-site.create`、`docfirst.attach`、`shell.reload` | [借用别的插件的命令](/docs/seams/borrowed-commands) |
| 6 | CDP 驱动（约定） | 开发套件 ↔ `cdp.mjs` ↔ 工作台页面 | 命令行参数、输出的 JSON、`window.gwb.command` | [CDP 驱动](/docs/seams/cdp) |
| 7 | 内核与 home（约定） | `devkit.home.*`、CDP 驱动 ↔ 内核 exe | `GWB_HOME`、调试端口、`runtime.json`、home 根目录、`gwb.log` 的行格式 | [内核与 home](/docs/seams/kernel-home) |
| 8 | 条目树 | 插件管理 ↔ cordis loader | `EntryTreeLike` 的 store / create / update / remove / resolve | [条目树](/docs/seams/entry-tree) |
| 9 | pnpm 与包源 | 插件管理、开发套件 ↔ pnpm、npm 源、两份 npmrc、gitea 插件的设置 | 两个插件用同一个 pnpm（两个固定位置之一、核对版本）、发开发版与正式版；插件管理按 scope 找源、调 registry 的检索接口、读写 `~/.npmrc`、按名字调 `settings.get` 读 gitea 设置 | [pnpm 与包源](/docs/seams/pnpm-registry) |
| 10 | 被测仓的形状（约定） | 改一版看一版、发正式版、加插件 ↔ 被测插件仓 | 仓根 build 脚本、`files`、`keywords`、目录布局、git 工作区干净 | [被测仓的形状](/docs/seams/repo-shape) |
| 11 | 服务表与类型声明（约定） | `devkit.services` ↔ home 里各包的 `.d.ts` | `declare module 'cordis' { interface Context { … } }` 与类型定义 | [服务表与类型声明](/docs/seams/service-table) |

## 包

| 包名 | 在哪 | 讲什么 | 页 |
| --- | --- | --- | --- |
| `@godcreator/gwb-devkit` | `plugins/devkit` | 开发套件：写插件这条路上每一步的命令 | [gwb-devkit](/docs/devkit) |
| `@godcreator/gwb-plugin-manager` | `plugins/plugin-manager` | 插件管理：装卸包、增删条目、热升级、升内核、报告 peer 范围不包含当前内核的插件与 peer 里没满足的插件 | [gwb-plugin-manager](/docs/plugin-manager) |

## 怎么读这张图

- 图上只画模块与模块之间的接缝；每个包有哪些功能、提供什么接口，看各包自己的页
- 一条接缝连接的两个模块可以各自替换：只要接口不变，换掉其中一个，另一个不用改
- 每条接缝由什么测试保护，写在「细节在」那一列的页里；左栏接缝页标题前的数字就是图上的编号
- 内核那边对插件管理的承诺（home 布局、loader 与 include 的版本）在内核仓文档站的接缝页「home 布局与条目树」

## 按要做的事读

- **写一个新插件**：[写插件的规矩](/docs/rules)，再看[开发套件](/docs/devkit)的建仓、改一版看一版、发正式版
- **在本仓动手**（检查、在隔离 home 里验证、发版）：[开发](/docs/develop)
- **改插件管理**：[插件管理](/docs/plugin-manager)；它和内核之间的约定在[条目树](/docs/seams/entry-tree)，和开发套件之间的在[devkit 调插件管理](/docs/seams/plugin-manager-calls)
- **改建仓模板或发版前检查**：[模板与发版前检查](/docs/seams/template-release)；改服务总览：[服务表与类型声明](/docs/seams/service-table)
- **在页面里点击、读数、截图**：[CDP 驱动](/docs/seams/cdp)
- **词不认得**：[术语表](/docs/glossary)
