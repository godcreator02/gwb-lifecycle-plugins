# 开发套件

**本页回答**：这个包是什么、它管到哪儿为止、这个站该按什么顺序读。

`@godcreator02/gwb-devkit` 是**一个普通的 gwb 件**。它没有任何特权：装进 home 才有它的命令，
挂不上就什么都没有，跟 hello 一个待遇。这一点是理解它的起点，它看起来像「工具链」，但它跟工具链
最大的区别是**它自己也得走它教别人走的那条路**（起独立仓、发本机源、装进 home），而且它确实是
那么来的。

它解决的问题只有一个：**「在一个新文件夹里开发一个新件」这条路上，每一步都有个能被 agent 调到
的口。** 建仓要有口、本机源的起停要有口、开一个干净的测试 home 要有口、把改动送进那个 home 再
证明送到了要有口。没有这些口，每一步都是一段要人记在脑子里的 PowerShell。

## 它管哪五件事

| | 是什么 | 口 | 细看 |
| --- | --- | --- | --- |
| 建仓 | 把一个新件的骨架落进一个新文件夹，默认连文档站一起（站那半两步转给别的件） | `devkit.scaffold` | [建仓](/docs/scaffold) |
| 手册 | 写件的整条路、红线、验机怎么走，随包发。**只挂自己那份** | `skills/` 经 `gwbSkills` 挂载 | [手册正本](/outputs/skills/gwb-devkit) |
| 本机源 | 本机 Verdaccio 的起 / 停 / 状态 / 日志，另有一扇窗格 | `registry.*` | [本机源](/docs/registry) |
| 测试 home | 测试 home 的开 / 列 / 重开 / 停 / 删 | `devkit.home.*` | [测试 home](/docs/home) |
| 改一版看一版 | 把工作区的改动送进另一个 home 正在跑的进程，并且证明送到了 | `devkit.dev` / `devkit.dev-check` | [改一版看一版](/docs/dev) |

外加一条经 `gwbNodeCli` 登记的外部 CLI：**`devkit.cdp`**，在一个工作台页面里动手。
[那支驱动](/docs/cdp) 讲它管到哪儿为止。

**它不管文档站。** 站的一生归站件、站里内容的正确性归 docfirst 件。本包**不依赖那两个件的任何
包**：建仓时要用它们，只按名字在命令总线上找两条命令。

**CLI 形态的东西一律经 `gwbNodeCli` 登记，不做总线命令、不进程内调。** 理由不是洁癖：node-cli
登记的命令自动镜像成同名总线命令，于是自动是 MCP 工具，回执自带 stdout、stderr 与退出码。
自己写一遍 spawn 与超时，换来的是同一件事的第二种回执形状。

## 按这个顺序读

想知道**怎么用**，去[怎么用](/docs/start)，那页管装、设置项、门禁与每条命令的入口。

想知道**怎么拆的**，先读[总索引](/docs/system-map)：依赖方向、纯逻辑与真机器切在哪一刀、
模块总表与代码地图都在那儿；再按兴趣挑一张模块页。

想知道**为什么变成现在这样**，去[轨迹](/trajectory)。想知道**接下来去哪**，去[未来](/future)。
词不认得去[术语](/docs/glossary)。
