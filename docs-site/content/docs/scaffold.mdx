# 建仓

**本页回答**：`devkit.scaffold` 从收到参数到回执之间做了什么、哪几步不许换顺序、站那半为什么不在本包。

## 管什么

一个短名派生出整套身份：包名、插件名、命令名的前半。这块把包内 `template/` 那套骨架照这份身份
渲染好，落进一个还不存在的目录，再把「接下来做什么」连同回执一起交出去。

插件那半落盘之后才轮到文档站，而建站是两步，两步都不是本包的命令。

## 不知道什么

它不知道 fumadocs 是什么，不知道钉码是什么，也不知道命令总线存在。纯机那半连 `ctx` 都拿不到。
**连「站建成没有」都是别人告诉它的**：`nextSteps` 收一格 `site`，按那一格分支，不按调用方想不想建站分支。

它也不知道生成出来的那个仓将来怎么发版。模板里写着那条 `pnpm publish`，但那是模板的内容，
不是这块的行为。

## 提供的接口

对外只有一条命令 `devkit.scaffold`，参数 `{ name, dir, title?, docs?, port? }`。**参数不对时它把
整份说明回给调用方**，不是回一句「参数错误」：这条命令的主要调用方是 agent，命令总线不带参数形状，
它认得出自己错在哪全靠这句话。

模块内部导出的是一串纯函数，接线那边按顺序串起来：

{/* ref file="../src/scaffold.ts" lines="85-108" */}

校验、派生、绝对化、缺省值全在这一处完成，一次都没碰盘。抛出来的每一句都说得出该怎么改。

**整套模板先在内存里渲染完再碰盘。** 占位符出错是这条路上最可能的失败，而目标目录一旦开始写就
没有干净的回滚点。

{/* ref file="../src/scaffold.ts" lines="162-172" */}

认不出的占位符当场抛。留一个 `{{typo}}` 在生成的仓里，它会一路活到别人的 `package.json` 里去，
那时已经没人知道它本来该是什么。所以给模板加了新占位符，`placeholders()` 必须同时加一格。

{/* ref file="../src/scaffold.ts" lines="202-211" */}

目标目录必须还不存在。建仓是一次性动作，往已有目录里铺文件没有干净的回滚点。

## 依赖的接口

| 接口 | 用来做什么 | 生产实现 | 测试实现 |
| --- | --- | --- | --- |
| `node:fs` | 读包内模板、把渲染好的文件写下去 | 直接调，不注入 | 不替换，真写临时目录 |
| 包内 `template/` | 骨架正本，`packageRoot()` 向上找 `package.json` 定位 | 发出去的包里那份 | 同一份，测试读的就是它 |
| `docs-site.create` | 铺 fumadocs 骨架 | 站点插件提供，总线上按名字找 | 不测：装没装都不影响插件那半落盘 |
| `docfirst.attach` | 在骨架上装六区 | docfirst 插件提供，同上 | 同上 |

**站那半是两步，顺序不能反，中间不许插事。**

{/* ref file="../src/index.ts" lines="537-549" */}

`docfirst.attach` 只在还没写过内容的骨架上装得了，它自己守着这条。建骨架与装六区连着跑，中间没人
碰过文件，整个覆盖才是安全的；给一个跑了半年的站自作聪明地 AST 改写不是。`scaffold` 里这两条紧挨着，
正是那个安全的时刻。

**站没建成不算建仓失败。** 插件那半早已落盘，所以回执里那两格才是真相：

`built` 说骨架铺没铺，`attached` 说六区装没装，`nextSteps` 按这两格分三支。回执里给一条不存在的
`cd docs-site` 比不给还坏，所以连生成的 README 里讲站的那段话，都是在渲染之前按「站点插件在不在」定下来的。

## 怎么单独测

喂一份入参，看抛什么、算出什么；喂一个临时目录，看盘上落下什么。整块不起进程、不开窗，
所以 `tests/scaffold.test.ts` 把这几件事直接钉住：

短名的正则放不放得过 `x--` 这种尾巴；`planScaffold` 的派生与缺省；`docsBlock` 在建站与不建站两种
局面下说的是两段不同的话；`nextSteps` 按 `built` 与 `attached` 分出的三支各说了什么；认不出的占位符
真的会抛；`.tpl` 后缀真的脱掉了；包内 `template/` 里那几个文件真的都在；`writeRepo` 对已存在的目录
真的拒。

模板文件清单那一条是这里最容易被忽略的守卫：`files` 白名单漏掉 `template`，包照发、也照装得上，
直到有人调 `devkit.scaffold` 才报「包内 template/ 不在」。

## 代码地图

**在哪**：纯机全在 `src/scaffold.ts`，接线与站那半在 `src/index.ts` 的 `devkit.scaffold` 那一段与
`buildDocsSite`，骨架正本在包根 `template/`。

**先读**：`planScaffold`，那是整条链的入口与全部校验。

**读序**：`planScaffold` 算出计划，`placeholders` 与 `render` 把模板变成内存里的文件表，
`writeRepo` 落盘，`nextSteps` 生成回执尾巴。站那半在这之后，由 `index.ts` 经总线发出去。

**可跳过**：`template/` 下那十个 `.tpl` 是给别的仓用的内容，不是这块的逻辑。要看模板长什么样就去看
那个目录本身，这一页不抄。
