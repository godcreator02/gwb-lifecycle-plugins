# 建仓与加件

**本页回答**：`devkit.scaffold` 与 `devkit.scaffold.plugin` 从收到参数到回执之间做了什么、哪几步不许换顺序、站那半为什么不在本包。

## 只有一种仓形

薄壳 workspace：根是 private 壳（`pnpm build` / `pnpm check` 递归到成员，自己没有代码），
件住 `plugins/<短名>/`，非件包住 `packages/`（repo-kit 那类仓侧工具，按需）。**「单件仓」不是
另一种仓形**，只是 `plugins/` 下恰好一个目录；加第二个件永远是 `devkit.scaffold.plugin`
往 `plugins/` 再铺一个，不存在「当初建小了、现在要迁移」的悬崖。件包内部自足
（src / tests / tsconfig / vitest / oxlint 配置全在包内）——不管这个包住在哪个仓，形状不变。

模板分两区，这是格式统一的物理保证：`template/repo/` 铺仓根（薄壳半），`template/pkg/`
铺 `plugins/<短名>/`（件包半，**唯一正本**——建仓与加件落的是同一份）。在役的老裸根单件仓
（仓根即包根）不迁，随触随迁；`devkit.scaffold.plugin` 收到这种仓当场拒，报错里带迁移的路。

## 管什么

一个短名派生出整套身份：包名、插件名、命令名的前半。这块把包内 `template/` 两区按这份身份
渲染好、落进一个还不存在的目录，再把「接下来做什么」连同回执一起交出去。

插件那半落盘之后才轮到文档站，而建站是两步，两步都不是本包的命令。加件不碰站——一份站
盖全仓，件清单的更新归 docfirst（`nextStepsPlugin` 最后一步提醒）。

## 不知道什么

它不知道 fumadocs 是什么，不知道钉码是什么，也不知道命令总线存在。纯机那半连 `ctx` 都拿不到。
**连「站建成没有」都是别人告诉它的**：`nextSteps` 收一格 `site`，按那一格分支，不按调用方想不想建站分支。

它也不知道生成出来的那个仓将来怎么发版——README 里教的那条 `devkit.release` 是模板的内容，
不是这块的行为。

## 提供的接口

对外两条命令：`devkit.scaffold { name, dir, title?, docs?, port? }` 与
`devkit.scaffold.plugin { name, repo, title? }`。**参数不对时它们把整份说明回给调用方**，不是回一句
「参数错误」：这两条命令的主要调用方是 agent，命令总线不带参数形状，它认得出自己错在哪全靠这句话。

模块内部导出的是一串纯函数，接线那边按顺序串起来：

校验、派生、绝对化、缺省值全在这一处完成，一次都没碰盘。抛出来的每一句都说得出该怎么改。

加件的计划**真读盘**（建仓那条不读）——repo 必须已经是个薄壳 workspace 才收：

{/* ref file="../plugins/devkit/src/scaffold.ts" lines="150-178" */}

**整套模板先在内存里渲染完再碰盘。** 占位符出错是这条路上最可能的失败，而目标目录一旦开始写就
没有干净的回滚点。

{/* ref file="../plugins/devkit/src/scaffold.ts" lines="251-257" */}

认不出的占位符当场抛。留一个 `{{typo}}` 在生成的仓里，它会一路活到别人的 package.json 里去，
那时已经没人知道它本来该是什么。所以给模板加了新占位符，`placeholders()` 必须同时加一格。

两区落点是一条纯函数：`repo/` 铺仓根、`pkg/` 铺 `plugins/<短名>/`，**区外的文件当场抛**——
模板里每个文件都得声明自己落哪，没声明的落下去就是一棵没人认领的树。

{/* ref file="../plugins/devkit/src/scaffold.ts" lines="269-277" */}

建仓渲染两区一起；加件只渲染件包那半，rel 相对件包根——`writeRepo` 的「目标必须还不存在」
正好落在 `plugins/<短名>/` 上，仓根与站一概不碰。

{/* ref file="../plugins/devkit/src/scaffold.ts" lines="294-313" */}

目标目录必须还不存在。建仓与加件都是一次性动作，往已有目录里铺文件没有干净的回滚点。

{/* ref file="../plugins/devkit/src/scaffold.ts" lines="316-324" */}

## 依赖的接口

| 接口 | 用来做什么 | 生产实现 | 测试实现 |
| --- | --- | --- | --- |
| `node:fs` | 读包内模板、验仓形状、把渲染好的文件写下去 | 直接调，不注入 | 不替换，真写临时目录 |
| 包内 `template/`（两区） | 骨架正本，`packageRoot()` 向上找 `package.json` 定位 | 发出去的包里那份 | 同一份，测试读的就是它 |
| `docs-site.create` | 铺 fumadocs 骨架 | 站点插件提供，总线上按名字找 | 不测：装没装都不影响插件那半落盘 |
| `docfirst.attach` | 在骨架上装六区 | docfirst 插件提供，同上 | 同上 |

**站那半是两步，顺序不能反，中间不许插事。**

{/* ref file="../plugins/devkit/src/index.ts" lines="707-718" */}

`docfirst.attach` 只在还没写过内容的骨架上装得了，它自己守着这条。建骨架与装六区连着跑，中间没人
碰过文件，整个覆盖才是安全的；给一个跑了半年的站自作聪明地 AST 改写不是。`scaffold` 里这两条紧挨着，
正是那个安全的时刻。

**站没建成不算建仓失败。** 插件那半早已落盘，所以回执里那两格才是真相：

{/* ref file="../plugins/devkit/src/index.ts" lines="648-660" */}

`built` 说骨架铺没铺，`attached` 说六区装没装，`nextSteps` 按这两格分三支。回执里给一条不存在的
`cd docs-site` 比不给还坏，所以连生成的 README 里讲站的那段话，都是在渲染之前按「站点插件在不在」定下来的。

## 怎么单独测

喂一份入参，看抛什么、算出什么；喂一个临时目录，看盘上落下什么。整块不起进程、不开窗，
所以 `tests/scaffold.test.ts` 把这几件事直接钉住：

短名的正则放不放得过 `x--` 这种尾巴；`planScaffold` 的派生与缺省；`planScaffoldPlugin` 对
不在的 repo、没有 plugins/ 那条的 yaml（老裸根仓）三种拒；`docsBlock` 在建站与不建站两种
局面下说的是两段不同的话；`nextSteps` / `nextStepsPlugin` 各分支说了什么、packages 参数有没有
带上；认不出的占位符真的会抛；`.tpl` 后缀与两区落点（`landRel`）真的对；包内 `template/`
里每个文件都声明了住哪一区；端到端在临时薄壳仓里真落一个 `plugins/<短名>/`；`writeRepo`
对已存在的目录真的拒。

模板文件清单那一条是这里最容易被忽略的守卫：`files` 白名单漏掉 `template`，包照发、也照装得上，
直到有人调 `devkit.scaffold` 才报「包内 template/ 不在」。

**薄壳新根形在真实 pnpm 里站不站得住，单元测试答不了**——探针
`probes/2609191042_workspace-scaffold/` 用构建产物真铺了一个仓跑完 install / build / check，
单成员的 `--filter "./plugins/*"`、oxlint 从件包 cwd 找配置、根壳 check 递归，三样全过。

## 模板里两处看着多余、其实少不了

- **`pnpm-workspace.yaml` 里的 `allowBuilds`**：pnpm 11 起设置住这个文件，`package.json` 的 `pnpm` 字段
  不再读；esbuild 的构建脚本要在这儿批。不批的现象是连环的：install 报「Ignored build scripts」，
  `pnpm run` 的依赖核验自动补装再撞同一块石头，最后的栈在 pnpm 自己肚子里，看不出是构建脚本没批
- **`oxlint-tsgolint`**：`oxlint` 的 type-aware 规则要它，少了 `pnpm lint` 报 "Failed to find tsgolint executable"。
  模板里它与 `oxlint` 两个都钉版

## 代码地图

**在哪**：纯机全在 `src/scaffold.ts`，接线与站那半在 `src/index.ts` 的 `devkit.scaffold` /
`devkit.scaffold.plugin` 两段与 `buildDocsSite`，骨架正本在包根 `template/repo/` 与 `template/pkg/`。

**先读**：`planScaffold`，那是建仓那条链的入口与全部校验；加件那条从 `planScaffoldPlugin` 进。

**读序**：计划算出来，`placeholders` 与 `render` 把模板变成内存里的文件表，`landRel` 决定两区
各自落哪，`writeRepo` 落盘，`nextSteps` / `nextStepsPlugin` 生成回执尾巴。站那半在这之后，
由 `index.ts` 经总线发出去。

**可跳过**：`template/` 下那 18 个 `.tpl` 是给别的仓用的内容，不是这块的逻辑。要看模板长什么样
就去看那两个目录本身，这一页不抄。
