# 软件源发现（候选）

**本页回答**：源收敛到「每人一个 gitea 个人源」之后，装别人的件还差哪一步手工、
把它收成命令的候选长什么样、边界在哪。**候选就是候选，没拍板**——真要做，先按
选型那条路走一遍，拍板后落轨迹卡，再回来改这一页与[路线图](/future/roadmap)。

## 背景：只剩一步手工

源已经收敛：每人一个 gitea 个人源，`@<用户名>/*` 的包住 `git.tianshen02.online`
上各自的 `/api/packages/<用户名>/npm/`，scope＝owner 名是 gitea 钉死的硬约束。
发布侧因此零配置（token 在自己 npmrc 里）；**消费侧还差一步**——装别人的件，
得先知道那个人存在，再往用户级 `~/.npmrc` 手写一行 scope 路由。人少时无所谓，
人一多这步就是唯一的手工瓶颈，而且写错一行整个 scope 装不上。

## 候选形态：三条口

`pkg.discover` 家族（名字候选，挂在 devkit 下）：

| 口 | 干什么 |
| --- | --- |
| `scan` | 枚举 gitea 用户（`/api/v1/users/search`），逐人探 `/api/packages/<用户名>/npm`，收「谁有源、各有哪些包」 |
| `list` | 报当前已发现与已接入的源和包 |
| `sync` | 把发现的源写进用户级 `~/.npmrc` 的 scope 行 `@<用户名>:registry=<源URL>` |

关键的便宜在 `sync` 那步：**scope＝owner 名这条硬约束让路由行可以从发现结果直接推导**——
用户名是探出来的、源 URL 是拼出来的，不需要人写，也就写不错。

## 信任模型：发现只给路由，不给信任

npmrc 里多一行 scope 路由 ≠ 那个源可信。三道现成的闸照旧生效：

- `minimumReleaseAge` 对非豁免 scope 照拦——发现新源不会顺手放行新鲜包；
- 装不装、钉哪个版本，永远是各仓自己的决定，`sync` 只管「装得到」；
- scope 抢注面天然小：每行路由都指回 `git.tianshen02.online` 的个人源，
  同名 scope 落不到公网 npmjs 上去。

## 明确不做

- 不做「信任某人」名单——谁发现谁装，责任链保持显式；
- 不自动安装、不替人抬版本；
- 不做 org/team 聚合源——试过一条（team 组织），已整体撤掉，个人源就是收敛点。
