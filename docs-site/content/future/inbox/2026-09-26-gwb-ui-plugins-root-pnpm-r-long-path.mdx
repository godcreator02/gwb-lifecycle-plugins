## 现场

实测插件用 `devkit.scaffold` 建在
`C:\Users\<用户>\AppData\Local\Temp\claude\<会话目录>\scratchpad\pane-probe`。仓根 `pnpm build` / `pnpm check`
（模板 `plugins/devkit/template/repo/package.json.tpl:7-8` 的 `pnpm -r …`）失败，报 `os error 3`：pnpm 12 在
`node_modules\.pnpm-task-run-state-v1\` 下写的文件路径有 274 个字符，超过 Windows 的 260 上限。改成
`pnpm -C plugins/pane-probe run build` 就能跑。`devkit.dev`、`devkit.release` 都在仓根运行 `pnpm build`，同样会撞上。

## 期望

至少一条：
- `devkit.scaffold` 在目标路径过长时直接拒，写明上限与原因
- 说明书 gwb-devkit 的建仓一步提醒仓别放在路径很长的目录
- 模板仓根脚本不依赖 `pnpm -r` 的任务状态目录（看 pnpm 有没有关掉它的配置）
