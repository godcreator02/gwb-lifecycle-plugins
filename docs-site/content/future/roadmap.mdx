# 路线图

**本页回答**：这个件走到哪一步了、接下来可能去哪、哪些只是候选还没拍板。

**候选就是候选。** 这一页里带「候选」两个字的条目一律没拍板，别照着它动手：真要做，
先按选型那条路走一遍、拍了板、落一张[轨迹卡](/trajectory)，再回来改这一页。

## 阶段

| 阶段 | 目标 | 完成的标志 |
| --- | --- | --- |
| 一 | 四件事各开一个口 | 建仓、手册、本机源起停、测试 home 的开收都有命令，手册与件模板随包发 |
| 二 | 内循环成形 | 「改一版看一版」收成一条命令，一趟走完到取证；文档站转成六区 |
| 三（候选） | 内循环不再需要手工准备 | 开一个隔离 home 就能直接当靶子，不用先手装几个件 |

## 当前阶段

**第二阶段**。内循环这条链本身已经实机走通：从控制台那个 home 出发，构建、发开发版、
装进目标 home、重挂、刷新、取证一趟走完，换别人的件与换本件自己两趟都验过。

这个阶段还没收口的是它**周围**的东西，也就是下面三条。

## 下一步：三件已经知道的事

**一、隔离 home 的底座还是手工的。** 开一个新的测试 home，开出来是个空 home：内核只铺最小
形态，里头一个件都没有。要拿它当靶子，得先手动把总线、外壳、件管理那几个件装进去，
再手写条目。这一步没有命令，是本轮**有意没做**的缺口，不是遗漏。

候选做法是给开 home 那条命令加一格「照着某个已有 home 的清单铺」，名单从那个 home 现读，
不写死在本包里。写死一份基线名单是另一个候选，代价明显：生态里的件在增减，那份名单过期
了不报错。两个都没拍板。

**二、一趟的成本。** 内循环一趟大约一分钟，绝大部分花在发版与在目标 home 里装那两步上，
重挂与刷新本身很快。比起「覆盖 dist」那条十几秒的近路，这一分钟买到的是：不写穿 pnpm 的
全局仓、node 那半真的换得动、home 里版本号跟内容对得上。这笔账是划算的，所以先不优化。

真要压，候选是在本机打包再直接装那个包文件，省掉发到源上再从源上装那一趟。代价也清楚：
绕开了源，就证不到「这个包从源上装得下来」这件事，而那正是「一定要真装」这条纪律要证的。
没拍板。

**三、开发版会攒垃圾。** 每跑一趟就在本机源与 pnpm 的全局仓里留下一个一次性版本。它们标
`dev`、不动 `latest`，所以不影响别人装包，但攒多了占盘。眼下的处置就是记得偶尔跑一次
`pnpm store prune`，没做成自动的：自动清理要判「哪些还在某个 home 里用着」，判错了就是
把一个正跑着的 home 的依赖删了。

## 顺带等着的一件

内循环里往目标 home 装包走的是 `pnpm add` 加已有条目，**有意绕开了件管理那条装机命令**：
那条命令对已经装过的包也会再建一条条目，同一个件挂两遍。这个绕法是本仓的，问题在件仓那边，
已经投了反馈。那头修了之后，这儿的绕法可以去掉，那时记得回来删这一段。

## 阶段切换时

把新阶段写进上面那张表，落一张轨迹卡，顺手复审[明确不做](/future/overview)里的每一条
还成不成立。上一次就有一条真的变了。
